Chunk-GDN PrefillChunk-GDN 预填充

How ATREX runs Gated DeltaNet prefill on Blackwell: the per-token recurrence, the chunked form that turns it into seven GEMMs and one triangular inverse, the 12-warp SM103 kernel that pipelines them, and the SM120 kernel built from the same math.

ATREX 如何在 Blackwell 上运行 Gated DeltaNet 预填充：逐 token 的递推，把它化为七个 GEMM 加一次三角求逆的分块形式，把这些步骤流水化的 12-warp SM103 kernel，以及由同一套数学写成的 SM120 kernel。

§1What the operator computes这个算子算什么

Gated DeltaNet keeps one matrix of state per value head and updates it once per token. The repository's own reference implementation, in the SM103 test, spells out the math in a few lines test_chunk_gdn_sm103.py:72–112. The state S is K × V = 128 × 128 in FP32, 64 KiB per head. For each token the head decays the state, predicts the value from the key, and writes back a gated share of the error:

Gated DeltaNet 为每个 value head 保存一个状态矩阵，每个 token 更新一次。仓库自带的参考实现写在 SM103 测试里，只有几行 test_chunk_gdn_sm103.py:72–112。状态 S 为 K × V = 128 × 128 的 FP32 矩阵，每个 head 64 KiB。对每个 token，head 先衰减状态，用 key 预测 value，再把误差按门控比例写回：

decayS̃ = αt · St−1
errorΔt = βt · (vt − S̃ᵀkt)
writeSt = S̃ + kt Δtᵀ
readot = s · Stᵀqt,   s = 128−1/2

The caller passes g as a log-decay and the kernels use α = exp(g); the tests draw g from logsigmoid, so α ∈ (0, 1), and β from a sigmoid test:57–58. Q and K are L2-normalized first. In the SM103 contract 4 Q/K heads serve 32 value heads, so each Q/K head is shared by 8 value heads test:82–91 chunk_gdn_cutedsl.py:10–18.

调用方把 g 作为对数衰减传入，kernel 使用 α = exp(g)；测试中 g 取自 logsigmoid，因此 α ∈ (0, 1)，β 取自 sigmoid test:57–58。Q 与 K 先做 L2 归一化。在 SM103 契约中，4 个 Q/K head 服务 32 个 value head，每个 Q/K head 由 8 个 value head 共享 test:82–91 chunk_gdn_cutedsl.py:10–18。

Run literally, this is a serial chain of rank-1 updates on a 64 KiB matrix, one per token. Prefill processes thousands of tokens, so both ATREX kernels work on 64 tokens at a time and turn most of the chain into matrix products.

照字面执行，这是对一个 64 KiB 矩阵、每个 token 一次的串行 rank-1 更新链。预填充动辄数千个 token，所以 ATREX 的两个 kernel 都一次处理 64 个 token，把这条链的大部分变成矩阵乘。

§2From tokens to chunks从 token 到分块

Take one chunk of C tokens that starts from state S0. Let γt = α1⋯αt be the running product of gates inside the chunk and Tij = γi / γj the decay from token j to token i ≥ j. Unrolling the recurrence inside the chunk gives every token a corrected value ut that depends on the earlier tokens of the same chunk through a unit lower-triangular system. Solving it once per chunk yields everything else:

取一个从状态 S0 出发、含 C 个 token 的分块。令 γt = α1⋯αt 为块内门控的累乘，Tij = γi / γj 为从 token j 到 token i ≥ j 的衰减。在块内展开递推后，每个 token 得到一个修正后的 value ut，它通过一个单位下三角方程组依赖块内更早的 token。每个块解一次这个方程组，其余一切随之可得：

couplingMij = βi Tij (ki · kj) for j < i,  0 otherwise
valuesU = (I + M)−1 · diag(β) · (V − diag(γ) K S0)
outputO = s · ( diag(γ) Q S0 + (T ⊙ QKᵀ)lower U )
next stateSC = γC S0 + Kᵀ diag(γC / γj) U

    §3Inverting I + M, block by block逐块求 I + M 的逆

    The only step that is not a GEMM is (I + M)−1 for a 64 × 64 unit lower-triangular matrix. The kernel inverts it in place in shared memory, in four stages that double the solved size each time :4162–4168. The identity it relies on: a block lower-triangular matrix [A 0; C D] has inverse [A−1 0; −D−1C A−1 D−1]. Once the diagonal blocks are inverted, each larger level only needs two small matrix products for its bottom-left block.

    唯一不是 GEMM 的步骤，是求 64 × 64 单位下三角矩阵 (I + M)−1。kernel 在共享内存中原地求逆，分四个阶段，每阶段把已解出的尺寸翻倍 :4162–4168。它依赖的恒等式是：分块下三角矩阵 [A 0; C D] 的逆为 [A−1 0; −D−1C A−1 D−1]。对角块求逆之后，每一更大层级只需两次小矩阵乘来得到其左下块。

    Inverse求逆Two chunks of a pair, four stages一对 chunk，四个阶段

    Stage 1 is the only scalar part: one thread per row, seven pivot steps, pivots broadcast with shuffles. Stages 2 to 4 use warp-level MMA atoms, m16n8k8 for 8 → 16 and m16n8k16 for the larger levels, each computing C ← −D−1·C·A−1 :4237–4610. The work is split across the pair: in stages 1, 3 and 4 warps 0–1 work on the first chunk and warps 2–3 on the second, and in stage 2 each warp handles one 16 × 16 tile in both chunks :3999–4086. The SM120 kernel uses a shared implementation of the same idea, CollectiveInverse collective_inverse_hmma.py:9–60.

    阶段 1 是唯一的标量部分：每线程一行，七步主元消去，主元通过 shuffle 广播。阶段 2 到 4 使用 warp 级 MMA 原子，8 → 16 用 m16n8k8，更大层级用 m16n8k16，每一步都计算 C ← −D−1·C·A−1 :4237–4610。工作在这对 chunk 之间拆分：阶段 1、3、4 中 warp 0–1 处理第一个 chunk、warp 2–3 处理第二个；阶段 2 中每个 warp 在两个 chunk 里各处理一个 16 × 16 tile :3999–4086。SM120 kernel 使用同一思路的共享实现 CollectiveInverse collective_inverse_hmma.py:9–60。

    §4The SM103 kernelSM103 kernel

    One CTA owns one tile: a sequence, a value head, and one 64-row half of that head's 128 value rows. The M64 path splits every value head in two and gives Q, K, gate and β a zero stride along the new mode, so both halves read the same data without copies :461–500. Chunks are 64 tokens and the kernel walks them in pairs of 128; a sequence whose length is a multiple of 64 but not of 128 runs one padded chunk whose gates are 1.0 gdn_prefill.py:166–170.

    Two details make the pipeline cheap.     §5Scheduling tilestile 调度

    The recurrence forces one CTA to walk every chunk of its tile in order, so the only parallelism across the GPU comes from tiles. In the SM103 contract that is 64 per sequence: 32 value heads times two halves. The grid is persistent with min(tiles, SM count) CTAs, and CTA c takes tiles c, c + grid, … in head-major order tile_scheduler.py:29–38 chunked.py:1035–1048.

    递推迫使一个 CTA 按顺序走完其 tile 的全部 chunk，所以整张 GPU 上的并行只来自 tile。在 SM103 契约中每条序列有 64 个 tile：32 个 value head 乘以两半。grid 为常驻式，共 min(tile 数, SM 数) 个 CTA，CTA c 依次处理 tile c、c + grid、……，按 head 优先顺序 tile_scheduler.py:29–38 chunked.py:1035–1048。

    Scheduler调度器Who runs which tile哪个 CTA 跑哪个 tile

    Tile work is counted in 64-token chunks, rounded up to 128-token pairs, and every chunk is assumed to cost the same. The kernel reads the SM count from the device gdn_prefill.py:449–450; 148 here is only an example value. Hover a column to list its tiles.

    tile 的工作量以 64-token chunk 计，向上取整到 128-token 对，并假设每个 chunk 耗时相同。kernel 从设备读取 SM 数 gdn_prefill.py:449–450；这里的 148 只是示例值。把鼠标移到某一列上可查看它的 tile。

    The repository's performance gate uses exactly the first preset: three 4,224-token sequences, and the whole call from Python must return within 1.0 ms test:436–478. The widget shows why tile count matters more than token count here: once there are more tiles than SMs, some CTAs run two tiles back to back and set the kernel's length.

    仓库的性能门槛用的正是第一个预设：三条 4,224-token 的序列，整个调用（从 Python 起算）必须在 1.0 ms 内返回 test:436–478。组件展示了为何这里 tile 数比 token 数更重要：一旦 tile 多于 SM，有些 CTA 要连着跑两个 tile，它们决定了 kernel 的时长。

    Why the designs differ两种设计为何不同

    The code does not say why SM120 keeps the state in registers and uses warp MMA. My reading: SM120 parts do not have the tcgen05 instructions or tensor memory that the SM103 kernel is built on, so the SM103 design cannot be ported directly.
