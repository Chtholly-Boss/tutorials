ATREX InternalsATREX 源码导读

How Alibaba's ATREX package sends one public operator call to a kernel written for one exact GPU target: exports that import nothing until called, conservative device detection, eligibility checks that reject a call before anything launches, compilation keyed by everything that changes the binary, and a test gate that reads kernel names out of the profiler.

阿里巴巴的 ATREX 如何把一次公开算子调用送到为某个确切 GPU 目标编写的 kernel：调用前什么都不导入的导出接口、保守的设备识别、在任何启动之前就拒绝调用的资格检查、以一切会改变二进制的因素为键的编译缓存，以及从 profiler 里读取 kernel 名称的测试门槛。

§2Placement by target, not by language按实现目标放置，而不是按语言

The repository has four top-level roles README.md:8–20. python/atrex/ holds the public APIs and dispatch. src/<vendor>/<operator>/<arch>/ holds implementations, with common_utils/ reserved for helpers already proven across architectures. op_test/ mirrors src/ with one test file per operator target, and .agents/skills/ holds the integration workflow.

仓库顶层分为四种角色 README.md:8–20：python/atrex/ 放公开 API 与分派逻辑；src/<vendor>/<operator>/<arch>/ 放具体实现，common_utils/ 只收已在多个架构上证明过的公共代码；op_test/ 与 src/ 对应，每个算子目标一个测试文件；.agents/skills/ 保存接入流程。

The rule that shapes the tree is that "directory placement follows the implementation target, not its language." The CuTe DSL Python for Chunk-GDN on SM120 and the native CUDA for NVFP4 MoE on SM120 both live under an sm120/ directory. The skill says to identify the target from the compiler target, architecture-specific instructions and runtime guards, not from the file extension SKILL.md:15–17 26–38.

决定目录结构的规则是：“目录位置取决于实现目标，而不是实现语言。”SM120 上 Chunk-GDN 的 CuTe DSL Python 代码与 NVFP4 MoE 的原生 CUDA 代码都放在 sm120/ 目录下。skill 要求根据编译目标、架构专属指令和运行时保护来判断目标，而不是看文件扩展名 SKILL.md:15–17 26–38。

The wheel keeps that tree. A custom build_py copies src/ into the package as atrex/src without compiling it, together with the CUTLASS include/ and tools/util/include/ headers setup.py:24–56. That is why API modules import implementations as atrex.src.nvidia…, and why native kernels can still be compiled from source after installation.

wheel 保留了这棵目录树。自定义的 build_py 把 src/ 原样复制进包内的 atrex/src（不编译），同时复制 CUTLASS 的 include/ 与 tools/util/include/ 头文件 setup.py:24–56。所以 API 模块用 atrex.src.nvidia… 导入实现，原生 kernel 在安装之后仍能从源码编译。

§3From a public call to a kernel从公开调用到 kernel

A call passes four gates before any GPU work starts: a lazy proxy, device detection, implementation selection and eligibility. The last two are per operator; the first two are shared.

一次调用在任何 GPU 工作开始之前要经过四道关卡：lazy proxy、设备识别、实现选择和资格检查。后两道由各算子自己定义，前两道是共用的。

Exports that import on first call首次调用时才导入的导出接口

Every public name in atrex starts as a proxy. The first call imports the API module, looks up the real function, replaces the module-level name with it, and forwards the call __init__.py:13–39. Later calls go straight to the real function. A failed import leaves the proxy in place, so a later call can retry test_lazy_import.py:38–54.

atrex 的每个公开名字一开始都是 proxy。第一次调用时，它导入 API 模块、找到真正的函数、用它替换模块级名字，再转发调用 __init__.py:13–39。之后的调用直接进入真正的函数。导入失败时 proxy 保留原位，之后的调用可以重试 test_lazy_import.py:38–54。

The payoff is that import atrex costs almost nothing. The FA test runs import atrex in a fresh interpreter and asserts that neither atrex.api.flash_attn nor cutlass got loaded test_flash_attn_sm103.py:200–215.

好处是 import atrex 几乎没有开销。FA 测试会在新的解释器里执行 import atrex，并断言 atrex.api.flash_attn 和 cutlass 都没有被加载 test_flash_attn_sm103.py:200–215。

Detecting the target conservatively保守地识别目标

detect_device_target turns a Torch device into a DeviceTarget(family, arch, runtime_version, device_index). The order of its checks is the point. ROCm also answers through torch.cuda, so HIP is checked first. Alibaba's PPU exposes a CUDA-compatible runtime and reports capability 8.9, so an exact product-name table is checked before anything NVIDIA. Only a device with a CUDA runtime and a name starting with NVIDIA gets an smXY arch from its capability device_target.py:25–66. Each case has a test with a fake Torch test_device_target.py:26–52.

detect_device_target 把一个 Torch 设备转换成 DeviceTarget(family, arch, runtime_version, device_index)。关键在于检查顺序：ROCm 也通过 torch.cuda 暴露接口，所以先查 HIP；阿里 PPU 提供 CUDA 兼容的 runtime 且报告 capability 8.9，所以在任何 NVIDIA 判断之前先查精确的产品名表；只有带 CUDA runtime、且名称以 NVIDIA 开头的设备，才会由 capability 得到 smXY 形式的 arch device_target.py:25–66。每种情况都有用假 Torch 写的测试 test_device_target.py:26–52。

Selection, then eligibility先选择实现，再检查资格

The skill fixes the order for every operator: detect the runtime and architecture from the input tensor's device, check dtype, shape, layout, options and the required runtime version, then take the first eligible implementation in an explicit policy SKILL.md:51–63. A can_use_* probe must not compile, allocate large buffers, switch devices or mutate tensors. Each operator writes its policy differently:

skill 为每个算子规定了同样的顺序：从输入张量所在设备识别 runtime 与架构，检查 dtype、形状、布局、选项和所需的 runtime 版本，然后在明确的策略里取第一个符合条件的实现 SKILL.md:51–63。can_use_* 探测函数不能编译、不能分配大缓冲区、不能切换设备，也不能修改张量。各算子写策略的方式不同：

  • Chunk-GDN picks the sm103 or sm120 package, and each package reports is_available() from whether its CuTe DSL modules imported chunk_gdn/__init__.py:8–23. The two targets then enforce completely different contracts.
  • FlashAttention accepts only the verified AKA q4 domain on SM103 and raises NotImplementedError for everything else launch.py:183–218.
  • NVFP4 MoE maps (family, arch) to a module with a one-entry table and validates its arguments while it runs, since it has no can_use_* probe nvfp4_fused_moe.py:11–42.
  • Chunk-GDN 选择 sm103 或 sm120 包，每个包根据其 CuTe DSL 模块能否导入来报告 is_available() chunk_gdn/__init__.py:8–23。两个目标随后执行完全不同的约束。
  • FlashAttention 只接受 SM103 上已验证的 AKA q4 范围，其余一律抛出 NotImplementedError launch.py:183–218。
  • NVFP4 MoE 用只有一项的表把 (family, arch) 映射到模块，由于没有 can_use_* 探测函数，它在执行过程中校验参数 nvfp4_fused_moe.py:11–42。

在下面试试：选一个设备和一个算子，修改调用参数，看探针按代码执行的顺序逐项检查，在第一个失败处停下。

The explorer passes those. Device names for SM103 and SM120 are placeholders; detection only needs the "NVIDIA " prefix and the capability.

Two results are worth seeing on purpose. Set num_splits to 1, the default in the FA4 signature, and the SM103 path refuses the call: vLLM's caller has to ask for 0 explicitly. Then switch Chunk-GDN from SM103 to SM120 with H=4. The same call that SM103 accepts fails on SM120, because the two implementations were validated for different head layouts.

有两个结果值得特意看一下。把 num_splits 设为 FA4 签名中的默认值 1，SM103 路径就会拒绝：vLLM 的调用方必须显式传 0。再把 Chunk-GDN 从 SM103 切到 SM120 并保持 H=4：SM103 接受的同一次调用在 SM120 上失败，因为两个实现验证的是不同的 head 布局。

§4Compiling on demand按需编译

import atrex must not compile kernels. Each operator states whether compilation happens on the first API call, on the first launch of a specialization, or during an explicit prewarm, and caches by every value that changes the generated code or the device context SKILL.md:65–69. The CuTe DSL operators do this inside their own modules: the FA decode kernel compiles once per (device, capability) and refuses to compile inside CUDA Graph capture aka_decode_runtime.py:250–265, and Chunk-GDN offers chunk_gdn_fwd_cutedsl_prewarm_buckets to compile every bucket at model init chunk_gdn_cutedsl.py:685–709.

import atrex 不得编译 kernel。每个算子都要说明编译发生在首次 API 调用、某个特化的首次启动，还是显式的 prewarm 中，并以一切会改变生成代码或设备上下文的值作为缓存键 SKILL.md:65–69。CuTe DSL 算子在各自模块内完成这件事：FA decode kernel 每个 (device, capability) 编译一次，并拒绝在 CUDA Graph 捕获期间编译 aka_decode_runtime.py:250–265；Chunk-GDN 提供 chunk_gdn_fwd_cutedsl_prewarm_buckets，在模型初始化时编译所有分桶 chunk_gdn_cutedsl.py:685–709。

Native CUDA goes through one shared helper, atrex.core.cuda_kernel. It decorates a Python stub whose body never runs. The first call builds a Torch C++ extension from the listed sources and forwards to the compiled function, and the stub's build(device) attribute prewarms the same module compile_cu.py:308–355. This is how NVFP4 MoE declares its 20 sources:

原生 CUDA 代码统一走一个共用的辅助函数 atrex.core.cuda_kernel。它装饰一个函数体永远不会执行的 Python 存根：首次调用时用列出的源文件构建 Torch C++ 扩展，再转发到编译好的函数；存根的 build(device) 属性可以预热同一个模块 compile_cu.py:308–355。NVFP4 MoE 就是这样声明它的 20 个源文件的：

The build identity is a SHA-256 over the module name, device family, capability, Torch and CUDA runtime versions, the nvcc and C++ compiler version strings, the Python ABI tag, every flag, the arch suffix, and the bytes of every source file and every file under every include directory, CUTLASS included. Its first 16 hex digits name the build directory under ~/.cache/atrex/jit/, or ATREX_JIT_CACHE_DIR compile_cu.py:79–86 121–170. Two dictionaries in the process answer repeat calls, and a thread lock plus an fcntl file lock stop two processes from building the same directory at once compile_cu.py:241–305. The target flag comes from the live capability plus the suffix, so SM120 with suffix "f" compiles for sm_120f compile_cu.py:267–271.

build identity 是一个 SHA-256，输入包括模块名、设备 family、capability、Torch 与 CUDA runtime 版本、nvcc 与 C++ 编译器的版本字符串、Python ABI 标签、所有编译选项、arch 后缀，以及每个源文件和每个 include 目录下每个文件的内容（CUTLASS 也包括在内）。取前 16 个十六进制字符作为 ~/.cache/atrex/jit/（或 ATREX_JIT_CACHE_DIR）下的构建目录名 compile_cu.py:79–86 121–170。进程内有两个字典应对重复调用，线程锁加 fcntl 文件锁防止两个进程同时构建同一个目录 compile_cu.py:241–305。目标编译选项由实际 capability 加后缀得到，因此后缀为 "f" 的 SM120 会编译为 sm_120f compile_cu.py:267–271。

Reading the code读代码得出的结论

_load_cuda_extension re-reads and hashes every source and header each time it runs, before it consults either in-process cache compile_cu.py:225–252. NVFP4 MoE avoids paying that per call by wrapping build() in lru_cache(maxsize=1). When the identity is new but a matching directory already exists on disk, reuse is left to torch.utils.cpp_extension.load; I haven't traced how it decides.

_load_cuda_extension 每次运行都会在查询进程内缓存之前重新读取并哈希所有源文件和头文件 compile_cu.py:225–252。NVFP4 MoE 用 lru_cache(maxsize=1) 包住 build()，避免每次调用都付出这个代价。当 identity 在本进程中是新的、而磁盘上已存在对应目录时，是否复用由 torch.utils.cpp_extension.load 决定，我没有追踪它的判断逻辑。

§6The test gate测试门槛

An operator change is incomplete until its target test is added or updated in the same change README.md:22–25. Each operator target has exactly one test module, op_test/<vendor>/<operator>/test_<operator>_<arch>.py, which holds correctness against a standalone reference, dispatch and fallback, negative eligibility, prewarm, the profiler check and a bounded performance check SKILL.md:90–109. For example, the SM103 FA test fails if the public call takes more than 0.15 ms test_flash_attn_sm103.py:374–378.

算子改动只有在同一次改动中新增或更新了对应目标的测试，才算完成 README.md:22–25。每个算子目标恰好有一个测试模块 op_test/<vendor>/<operator>/test_<operator>_<arch>.py，其中包括对照独立参考实现的正确性、分派与回退、反向资格检查、prewarm、profiler 检查以及有上限的性能检查 SKILL.md:90–109。例如，SM103 FA 测试要求公开调用不超过 0.15 ms test_flash_attn_sm103.py:374–378。

Two small conftest.py files make the layout do the work. The root one refuses to run if atrex was imported from python/atrex instead of an installed wheel conftest.py:10–17. The NVIDIA one reads the arch from the end of the test's filename and skips the module unless the detected target matches nvidia/conftest.py:8–24:

两个很短的 conftest.py 让目录结构本身完成筛选。根目录那个在 atrex 是从 python/atrex 而非已安装的 wheel 导入时拒绝运行 conftest.py:10–17；NVIDIA 目录下那个从测试文件名末尾读出 arch，只有检测到的目标一致时才运行该模块 nvidia/conftest.py:8–24：

Test selection测试选择Which tests run on this machine?这台机器上会跑哪些测试？

A skip only means "not this machine's target". On a claimed target, the skill counts a missing compiler, profiler or reference as a failure and requires zero applicable skips SKILL.md:104–106. An operator migrated from another revision also has to pass a parity gate: in one GPU job, baseline and candidate are installed side by side, run through the same public API with identical inputs, and no production case may be more than 5% slower SKILL.md:121–136.

跳过只意味着“这台机器不是该测试的目标”。在声明支持的目标上，skill 把缺少编译器、profiler 或参考实现都算作失败，并要求相关测试零跳过 SKILL.md:104–106。从其他版本迁移过来的算子还要通过性能对等门槛：在同一个 GPU 任务中并排安装基线版本与候选版本，用相同输入走同一个公开 API，任何生产用例都不得慢超过 5% SKILL.md:121–136。

§7Build构建

./build.sh does four things build.sh:10–35:

./build.sh 做四件事 build.sh:10–35：

  1. Initializes the third_party/cutlass submodule. The wheel build fails without its headers.
  2. Builds the wheel with python -m build --wheel --no-isolation. No kernel is compiled at this step.
  3. Installs the newest dist/atrex-*.whl, which also resolves its runtime dependencies.
  4. Reinstalls only that wheel with --force-reinstall --no-deps. The version stays 0.2.0 during development, so pip would otherwise treat the fresh build as already installed.
  1. 初始化 third_party/cutlass 子模块，缺少其头文件时 wheel 构建会失败。
  2. 用 python -m build --wheel --no-isolation 构建 wheel，这一步不编译任何 kernel。
  3. 安装最新的 dist/atrex-*.whl，同时解析其运行时依赖。
  4. 用 --force-reinstall --no-deps 只重新安装这个 wheel。开发期间版本号保持 0.2.0 不变，否则 pip 会认为刚构建的包已经装过。

Tests then run against that installation in one pytest session. They never install ATREX themselves and never fall back to the source tree op_test/README.md:19–32.

随后所有测试在一个 pytest 会话中针对这份安装运行。测试从不自己安装 ATREX，也不会回退到源码树 op_test/README.md:19–32。

    The gated delta rule for linear-attention prefill, computed chunk by chunk. SM103 runs the 5,668-line AKA M64 persistent CuTe DSL kernel, SM120 runs a warp-specialized delta-rule kernel with its own compile cache, and both use a shared 64×64 triangular inverse on tensor cores.

    用于线性注意力预填充的 gated delta rule，按 chunk 逐块计算。SM103 运行 5,668 行的 AKA M64 持久化 CuTe DSL kernel，SM120 运行带自有编译缓存的 warp 专用化 delta-rule kernel，二者共用一个在 tensor core 上完成的 64×64 三角矩阵求逆。

  2. 02

    FlashAttention decode (SM103)FlashAttention 解码（SM103）

    The FA4 lower-level varlen interface on SM103, served by a paged grouped-query decode kernel adapted from FlashInfer plus a split reduction kernel. It is specialized for 16 query heads, one KV head, head dimension 256 and 4 query tokens per sequence.

    SM103 上的 FA4 底层 varlen 接口，由一个改编自 FlashInfer 的分页 grouped-query decode kernel 加一个 split 规约 kernel 提供。它专门针对 16 个 query head、1 个 KV head、head dim 256、每序列 4 个 query token。

    src/nvidia/flash_attn/sm103/{launch,aka_decode_runtime,aka_decode_cutedsl}.py

  3. 03

    NVFP4 fused MoE (SM120)NVFP4 融合 MoE（SM120）

    A native CUDA and CUTLASS pipeline for NVFP4 mixture-of-experts: routing sort and prefix sums, input-row expansion with FP4 scale factors, the up/gate and down grouped GEMMs, and dedicated small-M and E512/top-10 kernels picked by a second dispatch on M.

    面向 NVFP4 混合专家的原生 CUDA 与 CUTLASS 流水线：路由排序与前缀和、带 FP4 缩放因子的输入行展开、up/gate 与 down 两次 grouped GEMM，以及按 M 二次分派选出的小 M 与 E512/top-10 专用 kernel。
