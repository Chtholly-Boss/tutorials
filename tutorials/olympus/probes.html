§1Sites and regions站点与区间

A probe is spliced before an instruction. Olympus fixed the contract in M0: a site at index i runs before instruction i on every path that reaches i, branches to i included (they are retargeted to the island), and it fires whether or not i's own guard passes. G-Watch's SassTraceSite means the same, which is what lets both tools trace one sites file DECISIONS 10 splice/plan.py:24–32.

探针拼接在某条指令之前。Olympus 在 M0 就定下了约定：索引为 i 的站点，在每条到达 i 的路径上都先于指令 i 执行，跳转到 i 的分支也算（它们被重定向到 island），而且无论 i 自己的谓词是否成立都会触发。G-Watch 的 SassTraceSite 含义相同，所以两个工具可以追踪同一份站点文件 DECISIONS 10 splice/plan.py:24–32。

  • "After instruction k" is a site at k + 1. Check indices against kernel.sass, where the index is pc / 16 USAGE.md:327–337.
  • A site has a kind: ts records a timestamp; value records a register (32 or 64 bits, a GPR or a uniform register) plus a timestamp; smid records the SM id splice/plan.py:18–21.
  • Every site in the corpus is warp-level: one record per warp, stored by one elected lane (PLAN.md §6.2). A site inside a loop fires once per iteration, and a site that lanes reach separately fires once per lane group.
  • “在指令 k 之后”就是 k + 1 处的站点。索引要对照 kernel.sass 核对，索引等于 pc / 16 USAGE.md:327–337。
  • 站点有类型：ts 记录时间戳；value 记录一个寄存器（32 或 64 位，通用寄存器或 uniform 寄存器）外加时间戳；smid 记录 SM 编号 splice/plan.py:18–21。
  • 语料库中的站点都是 warp 级的：每个 warp 一条记录，由一个被选中的 lane 写出（PLAN.md §6.2）。循环里的站点每次迭代触发一次；各 lane 分头到达的站点，每个 lane 组触发一次。

Regions区间

A record is a point in time. A region pairs two of them in the same warp: any record of a start site opens it, any record of an end site closes it. Both are tuples, because a warp can leave through any of several EXITs. close: last closes at the last end record before the next start, which is what a warp's lifetime needs after predicated EXITs. open: first absorbs repeated starts, for polling loops whose head is the start site. A role ties a region to the warps that play it splice/plan.py:47–66. Both tools' records are paired by the same Olympus code, per warp in time order, so a comparison with G-Watch never depends on G-Watch's own pairing DECISIONS 10.

一条记录是一个时间点。区间把同一个 warp 中的两个时间点配成一对：任一 start 站点的记录打开它，任一 end 站点的记录关闭它。两者都是元组，因为一个 warp 可能从若干个 EXIT 中的任一个离开。close: last 在下一个 start 之前的最后一条 end 记录处关闭，带谓词的 EXIT 之后计算 warp 生命期正需要这个。open: first 吸收重复的 start，用于以 start 站点为循环头的轮询循环。role 把区间绑定到扮演该角色的 warp 上 splice/plan.py:47–66。两个工具的记录都由同一段 Olympus 代码按 warp、按时间顺序配对，所以与 G-Watch 的比较从不依赖 G-Watch 自己的配对逻辑 DECISIONS 10。

§2The probe templates探针模板

The paper describes two probe types paper §4.5. INIT sits at the kernel's entry: it loads the trace buffer's address from the parameter list, offsets it to this thread's slot and initializes a ring-buffer pointer, keeping three 32-bit registers live for the rest of the kernel. RECORD captures a timestamp or a register value, writes it with the probe's id into the slot, and advances the pointer. Olympus follows this and adds a third, the EXIT calibration, which the paper folds into its clock scheme (§3).

论文描述了两类探针 论文 §4.5。INIT 位于 kernel 入口：从参数列表中取出追踪缓冲区地址，偏移到本线程的 slot，初始化环形缓冲区指针，并在 kernel 的剩余部分一直占用三个 32 位寄存器。RECORD 采集一个时间戳或寄存器值，连同探针编号写入 slot，然后推进指针。Olympus 沿用这一设计，并增加第三种：EXIT 校准，论文把它归在时钟方案里（§3）。

The templates live in olympus/probes/templates.py. They never choose registers: the planner hands them the persistent registers and the temporaries that chapter 02's liveness proves dead at the insertion point. They contain no control flow, so the splicer can insert them verbatim: the elected lane is a predicate and the ring index is a mask. Constant bank 0 is read only through ULDC / LDC templates.py:1–31.

模板位于 olympus/probes/templates.py。它们从不自己挑寄存器：规划器把持久寄存器和临时寄存器交给它们，后者由第 02 章的活跃性分析证明在插入点是死的。模板中没有任何控制流，因此拼接器可以原样插入：被选中的 lane 用谓词表示，环的下标用掩码计算。常量 bank 0 只通过 ULDC / LDC 读取 templates.py:1–31。

INIT

  • Where. Before instruction 1, after the stack-pointer LDC R1, c[0x0][0x28] at 0 (G-Watch's place too). Instruction 1 must be reachable only by falling through from 0, so INIT runs exactly once per warp plan.py:12–14.
  • The buffer pointer. The runtime appends one 8-byte parameter to the kernel at the old parameter size rounded up to 8 (§5). INIT reads it with ULDC.64 from c[0x0][0x210 + param_offset]. DeepGEMM's parameters take 624 bytes, so the pointer sits at 624 = 0x270 and INIT reads c[0x0][0x480].
  • The slot index comes from the launch geometry in constant bank 0 (ntid at 0x0 / 0x4 / 0x8, nctaid at 0xc / 0x10 / 0x14), so it is right for any grid and block shape, partial warps included: block_linear = (ctaid.z · nctaid.y + ctaid.y) · nctaid.x + ctaid.x, then slot = block_linear · ⌈threads / 32⌉ + (tid_linear >> 5) templates.py:364–402. The constants go through ULDC into the counter register before it is zeroed, never as an ALU constant operand: the sm_90 encoder mis-scaled those offsets by 4, which Poseidon found when INIT's first slot math gave garbage DECISIONS 36.
  • The header's first half. The slot base is pointer + slot × slot_bytes (UIMAD.WIDE.U32), the counter is zeroed, and the elected lane writes %globaltimer, the SM clock and SR_VIRTUALSMID | 0x80000000 with one STG.128. sm_90 has no SR_SMID.
  • 位置。在指令 1 之前，即索引 0 处设置栈指针的 LDC R1, c[0x0][0x28] 之后（G-Watch 也放在这里）。指令 1 只能由 0 顺序执行到达，因此 INIT 在每个 warp 中恰好执行一次 plan.py:12–14。
  • 缓冲区指针。运行时给 kernel 追加一个 8 字节参数，位置是原参数大小向上取整到 8（§5）。INIT 用 ULDC.64 从 c[0x0][0x210 + param_offset] 读取它。DeepGEMM 的参数占 624 字节，所以指针位于 624 = 0x270，INIT 读取 c[0x0][0x480]。
  • slot 编号由常量 bank 0 中的启动几何算出（ntid 在 0x0 / 0x4 / 0x8，nctaid 在 0xc / 0x10 / 0x14），因此对任何 grid 与 block 形状都正确，包括不满 32 个线程的 warp：block_linear = (ctaid.z · nctaid.y + ctaid.y) · nctaid.x + ctaid.x，然后 slot = block_linear · ⌈threads / 32⌉ + (tid_linear >> 5) templates.py:364–402。这些常量先经 ULDC 读进计数器寄存器（它随后才被清零），从不作为 ALU 的常量操作数：sm_90 编码器把这类偏移放大了 4 倍，Poseidon 正是在 INIT 最初的 slot 计算得出乱值时发现的 DECISIONS 36。
  • 头部前半。slot 基址 = 指针 + slot × slot_bytes（UIMAD.WIDE.U32），计数器清零，被选中的 lane 用一条 STG.128 写出 %globaltimer、SM 时钟和 SR_VIRTUALSMID | 0x80000000。sm_90 上没有 SR_SMID。

RECORD: TS and VALUERECORD：TS 与 VALUE

A timestamp record is six instructions and a store. CS2R.32 reads the SM clock, and LEA.LO packs word 0 = (clock << id_bits) | (site id + 1). ULOP3 takes the ring entry, count & (depth − 1), and UIMAD.WIDE turns it into an address, slot base + entry × record bytes. ELECT picks one lane, which stores at +0x20, past the header; UIADD3 advances the count templates.py:549–576. A VALUE record adds one or two stores: a 32-bit value at +4 of an 8-byte record, or at +8 of a 16-byte record with +12 zeroed, and a 64-bit value at +8 so that its STG.64 is aligned. A uniform-register value passes through the word-0 register with a MOV.

一条时间戳记录是六条指令加一条存储。CS2R.32 读 SM 时钟，LEA.LO 打包出第 0 个字 = (时钟 << id_bits) | (站点编号 + 1)。ULOP3 取环的表项 count & (depth − 1)，UIMAD.WIDE 把它变成地址：slot 基址 + 表项 × 记录字节数。ELECT 选出一个 lane，由它存到 +0x20（越过头部）；UIADD3 推进计数 templates.py:549–576。VALUE 记录多一到两条存储：32 位值放在 8 字节记录的 +4，或 16 字节记录的 +8 并把 +12 清零；64 位值放在 +8，使 STG.64 对齐。uniform 寄存器中的值借第 0 个字的寄存器经 MOV 转一手。

EXIT calibrationEXIT 校准

Before every EXIT or KILL that can execute, predicated ones included, the elected lane reads %globaltimer and the SM clock again and writes them with the record count as one 16-byte store at +0x10, so the header's second half is always self-consistent. A warp that passes a predicated EXIT has its calibration overwritten by a later one, and the last one it runs is the one that stays templates.py:496–545. When no aligned quad of registers is dead, the header goes out as two STG.64, an STG.64 and two STG.32, a pair and one register, or five single registers; the last reads the timer's high word twice and fixes a low-word wrap without a branch templates.py:311–330.

在每个可能执行的 EXIT 或 KILL 之前（带谓词的也算），被选中的 lane 再读一次 %globaltimer 与 SM 时钟，连同记录数用一条 16 字节存储写到 +0x10，因此头部后半始终自洽。经过带谓词 EXIT 而没有退出的 warp，其校准会被后面的一次覆盖，最后执行的那次保留下来 templates.py:496–545。如果找不到对齐的四个死寄存器，头部就用两条 STG.64、一条 STG.64 加两条 STG.32、一对寄存器加一个，或者五个单独的寄存器写出；最后一种把计时器高字读两次，不用分支就修正低字的回绕 templates.py:311–330。

When no predicate or register is dead: the forms没有死谓词或死寄存器时：几种形式

The default elect form needs one dead GPR, a dead even pair of uniform registers and a dead predicate. Real kernels don't always have them, so the planner tries fallback forms in order, each proven standalone on H200 with 0 stray bytes plan.py:42–56:

默认的 elect 形式需要一个死 GPR、一对死的偶数 uniform 寄存器和一个死谓词。真实 kernel 不总能满足，所以规划器按顺序尝试若干后备形式，每一种都在 H200 上单独验证过，没有一个多余字节 plan.py:42–56：

  • noelect (no dead predicate): every active lane stores, and all store identical bytes. A GPR value is made uniform first with R2UR, which takes the first active lane, the same lane ELECT would pick.
  • psave (M7, no dead predicate but two dead GPRs): the elect borrows a cold live predicate. SEL Rs, RZ, 0x1, !P saves every lane's P, ELECT P overwrites it, the stores are guarded by it, and ISETP.NE.AND P, PT, Rs, RZ, PT restores it after the last guarded store has issued. A guard is read at issue, so plain order is enough templates.py:561–567. It is used only where it is shorter than the 32-lane form, which in practice means 64-bit GPR values (13 → 11 instructions); on matmul trace-mem it cut the overhead by 1.26 points DECISIONS 71.
  • borrow (no dead GPR): the elected lane lends a live register that no asynchronous operation holds. It is saved with @P R2UR, every write to it is guarded by the elect predicate, and @P MOV restores it, so no other lane ever sees it change. Dropping the restore makes the standalone test kernel fault, so the harness would catch a lending bug.
  • noelect（没有死谓词）：每个活跃 lane 都存储，而且存的字节完全相同。GPR 中的值先用 R2UR 变成 uniform，它取第一个活跃 lane 的值，也就是 ELECT 会选中的那个 lane。
  • psave（M7；没有死谓词但有两个死 GPR）：elect 借用一个“冷”的活谓词。SEL Rs, RZ, 0x1, !P 为每个 lane 保存 P，ELECT P 覆盖它，存储由它守护，ISETP.NE.AND P, PT, Rs, RZ, PT 在最后一条受守护的存储发射之后恢复它。谓词在发射时读取，因此按顺序排列就够了 templates.py:561–567。只在它比 32-lane 形式更短的地方使用，实际就是 64 位 GPR 值（13 → 11 条指令）；在 matmul trace-mem 上它把开销降了 1.26 个百分点 DECISIONS 71。
  • borrow（没有死 GPR）：被选中的 lane 借出一个没有被任何异步操作占用的活寄存器。先用 @P R2UR 保存，对它的每次写入都由 elect 谓词守护，最后 @P MOV 恢复，所以其他 lane 看不到它有任何变化。去掉恢复这一步，单独的测试 kernel 就会出错，因此测试框架能抓住借用中的错误。

      Why the state lives in uniform registers为什么状态放在 uniform 寄存器里

      INIT keeps three 32-bit registers live until the warp exits, the paper's count: the slot base as an even pair and the record counter. In warp mode they are uniform registers, UR60 / UR61 / UR62 in most of the corpus poseidon.md:18–24, for two reasons:

      INIT 让三个 32 位寄存器一直活到 warp 退出，与论文的数量相同：slot 基址是一对偶数寄存器，外加记录计数器。在 warp 模式下它们是 uniform 寄存器，语料库中大多是 UR60 / UR61 / UR62 poseidon.md:18–24，理由有两条：

      1. Divergence. Uniform state is shared by the whole warp, so when lane groups reach a site separately, each group's record takes the next ring entry.       2. USETMAXREG leaves them alone. A warp-specialized kernel reallocates its GPRs per role, which is why the paper splices an INIT after each role's reallocation paper §4.5. Uniform registers are not reallocated, so in warp mode one INIT at the entry serves every role; checked with two warpgroups that DEALLOC to 40 and TRY_ALLOC to 232.       1. 分歧。uniform 状态由整个 warp 共享，所以当各 lane 组分别到达一个站点时，每组的记录占用环的下一个表项。如果状态放在每个 lane 的 GPR 中，两组可能写到同一个表项。用奇偶 lane 分歧的站点验证过：每个 warp 中每组各落一次，占用相邻的表项。
      2. USETMAXREG 不动它们。warp 特化的 kernel 按角色重新分配 GPR，所以论文要在每个角色的重分配之后再拼一个 INIT 论文 §4.5。uniform 寄存器不参与重分配，所以在 warp 模式下，入口处的一个 INIT 就服务所有角色；用 DEALLOC 到 40、TRY_ALLOC 到 232 的两个 warpgroup 验证过。thread 模式把状态放在 GPR 中，确实按论文的做法：handoff 在分角色之前把计数器存起来，role_init 在每个角色的寄存器上限内重建 slot 基址 templates.py:453–492。
