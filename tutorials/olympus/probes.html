What a probe is探针是什么

A probe is a few SASS instructions that read a clock, pack a word and store it. The templates write those instructions for one architecture with every control bit neutral, and they never pick a register: the planner hands them dead ones. What the probes write is record format v1, a per-warp slot whose decoder can rebuild every timestamp from the slot's own two clock anchors, so the result does not depend on any assumed frequency. Both halves are proven on the GPU before a splicer or a runtime ever touches them.

探针就是几条 SASS 指令：读一个时钟，打包成一个字，写出去。模板为一种架构写出这几条指令，所有控制位保持中性，并且从不自己挑寄存器：规划器把死寄存器交给它。探针写下的是记录格式 v1，每个 warp 一个槽位，解码器能凭槽位自己的两个时钟锚点重建每一个时间戳，所以结果不依赖任何假设的频率。这两半在拼接器或运行时碰到它们之前，就先在 GPU 上证明过。

§1Contract契约

What this layer promises这一层的承诺

A template body is correct SASS for its arch with neutral control bits, ready to be scheduled. Probes and decoders agree on every bit of record format v1: per-warp slots, a 32-byte header, word0 = (clk << id_bits) | (site_id + 1), integer-ns calibration.

模板主体是对应架构上正确的 SASS，控制位中性，等待被调度。探针与解码器对记录格式 v1 的每一位达成一致：每 warp 一个槽位、32 字节头部、word0 = (clk << id_bits) | (site_id + 1)、整数纳秒校准。

olympus/probes → used by使用者 olympus/planner · olympus/trace/record.py → shared by共用于 olympus/probes and与 olympus/trace/decode.py

The planner (chapter 04) builds every island from these bodies: it asks a template what it needs (needs_init, needs_record, needs_exit), hands it dead registers in exactly that shape, and then schedules the body by choosing control bits. A body it gets back has stall 15, no scoreboards and no waits on every instruction, so nothing in it presumes a schedule templates.py:243–255. The decoder (chapter 01) reads what those bodies wrote. record.py is one of the four contract modules importable from anywhere, so the templates and the decoder share one definition of a slot rather than two copies of it record.py:34–78. Without the first promise the planner's search would have nothing sound to permute; without the second, a trace would decode into the wrong sites at the wrong times while every output stayed bit-exact.

规划器（第 04 章）用这些主体构造每一个 island：它先问模板需要什么（needs_init、needs_record、needs_exit），按这个形状交给它死寄存器，然后通过选择控制位来调度主体。拿回的主体每条指令都是 stall 15、不占 scoreboard、不等待，所以其中没有任何东西预设一种调度 templates.py:243–255。解码器（第 01 章）读这些主体写下的东西。record.py 是四个可从任何地方导入的契约模块之一，所以模板和解码器共用同一份槽位定义，而不是两份拷贝 record.py:34–78。没有第一条承诺，规划器的搜索就没有可靠的东西可以排列；没有第二条，一份追踪会在输出逐位一致的同时，把错的站点解到错的时间上。

§2Invariant不变量

Invariant不变量2

A probe uses only registers proven dead, including registers held by in-flight asynchronous operations until their release point.

探针只使用被证明已死的寄存器，包括被进行中的异步操作占用到其释放点为止的寄存器。

Checked by the templates themselves, which take registers only through Persistent and Temps, verify the shape, the alignment and the arch's register range, and refuse any overlap between persistent, temporary and recorded registers templates.py:129–147; by the dead-register check, which overwrites every register the analysis calls dead and requires bit-identical outputs, on every corpus kernel on both arches; and, for the templates' own correctness, by the standalone GPU proof of invariant 5: 11 of 11 configurations on 132 SMs, 0 stray bytes, outputs identical to the unprobed kernel (DECISIONS 40).

检查方式：模板自身只通过 Persistent 与 Temps 接收寄存器，核对形状、对齐和该架构的寄存器范围，并拒绝持久、临时与被记录寄存器之间的任何重叠 templates.py:129–147；死寄存器检查改写分析判定为死的每一个寄存器，并要求输出逐位一致，在两种架构的每个语料库 kernel 上通过；至于模板自身的正确性，由不变量 5 的独立 GPU 证明保证：11 个配置全部通过，132 个 SM，0 个多余字节，输出与无探针的 kernel 相同（DECISIONS 40）。

A weaker rule would let a template pick "a register that looks free", for instance one the kernel does not name nearby. The templates cannot know liveness, and they do not try: the proof that a register is dead lives in one place, the liveness analysis, and the planner carries it to the template as a handed-over register. That is why every body builder takes st: Persistent and t: Temps and raises on anything that is not the shape it asked for; a template cannot be made to write a register it was not given templates.py:1–7.

更弱的规则会允许模板挑一个"看起来空闲"的寄存器，比如 kernel 在附近没有点名的那个。模板不可能知道活跃性，也不去尝试：寄存器已死的证明只在一处，即活跃性分析，由规划器以"交付的寄存器"这一形式带到模板。所以每个主体构造函数都接收 st: Persistent 和 t: Temps，凡是不符合它所要求形状的一律抛错；没有人能让模板去写一个没有交给它的寄存器 templates.py:1–7。

§3How it works如何工作

The slot槽位

The device buffer is n_slots slots of slot_bytes each, one per warp, indexed by the linear warp id. A slot is a 32-byte header followed by a ring of ring_depth records, padded to a multiple of 32 bytes record.py:1–26. A record is one 32-bit word, (clk << id_bits) | (site_id + 1): the + 1 makes an all-zero word mean "never written", which is why the runtime zeroes the buffer and why the buffer check can insist that unfilled entries stay zero. A run whose sites record values widens every record to 8 bytes (a 32-bit value at +4) or 16 bytes (a 64-bit value at +8, so its store is aligned).

设备缓冲区是 n_slots 个各 slot_bytes 字节的槽位，每 warp 一个，按线性 warp 编号索引。一个槽位是 32 字节头部，之后是 ring_depth 条记录的环，补齐到 32 字节的倍数 record.py:1–26。一条记录是一个 32 位字，(clk << id_bits) | (site_id + 1)：这个 + 1 让全零的字表示"从未写过"，这就是运行时要清零缓冲区、缓冲区检查能坚持未填表项必须为零的原因。站点记录值的运行把每条记录加宽到 8 字节（+4 处一个 32 位值）或 16 字节（+8 处一个 64 位值，使其 store 对齐）。

INIT: the slot from the launch geometryINIT：从启动几何得到槽位

INIT runs once, right after ptxas's own instruction 0 (the stack-pointer load). It loads the buffer pointer from the appended parameter at c[0x0][param_base + param_offset], computes this warp's slot index from the launch geometry, points a persistent even UR pair at buffer + slot × slot_bytes, zeroes the persistent counter, and writes the header's first half as one 16-byte store (or two or three smaller ones when no aligned quad is dead) templates.py:499–545. The geometry is blockDim and gridDim read from constant bank 0 with the uniform constant load, never as an ALU constant operand: slot = block_linear × ⌈threads per block / 32⌉ + (tid_linear >> 5), so INIT is correct for any grid and block shape, partial warps included templates.py:453–495.

INIT 只运行一次，紧跟在 ptxas 自己的第 0 条指令（栈指针加载）之后。它从追加参数 c[0x0][param_base + param_offset] 加载缓冲区指针，由启动几何算出这个 warp 的槽位下标，让一对持久的偶数 UR 指向 buffer + slot × slot_bytes，把持久计数器清零，再用一条 16 字节 store 写出头部的前一半（没有对齐的死四元组时则用两三条更小的 store）templates.py:499–545。几何是用 uniform 常量加载从常量 bank 0 读出的 blockDim 与 gridDim，从不作为 ALU 常量操作数：槽位 = block_linear × ⌈每 block 线程数 / 32⌉ + (tid_linear >> 5)，所以 INIT 对任何 grid 和 block 形状都正确，包括不满的 warp templates.py:453–495。

RECORD: clock → pack → storeRECORD：时钟 → 打包 → 存储

A TS record is the cheapest thing that can be a record: CS2R.32 R, SR_CLOCKLO reads the clock in 4–6 cycles with no scoreboard; LEA.LO shifts it left by id_bits and ORs in site_id + 1; a ULOP3 masks the counter to the ring index and a UIMAD.WIDE turns it into the entry address; one STG.E stores the word 32 bytes past the slot base; UIADD3 advances the counter. A VALUE record adds the value's store. Warp mode stores from one lane: ELECT P picks it and guards the stores, so a dead predicate is part of the default form templates.py:736–768. When no predicate is dead there are two fallbacks: noelect, where all 32 lanes store the same bytes (a GPR value is first made uniform with R2UR), and psave, where the kernel's live predicate is borrowed, each lane saving its own bit in a dead GPR and ISETP restoring it after the last guarded store templates.py:670–687. The template contains no control flow: the splicer inserts islands verbatim and relocates nothing inside them, so the elected lane is a predicate and the ring index a mask.

TS 记录是能称为记录的最便宜的东西：CS2R.32 R, SR_CLOCKLO 用 4–6 个周期读时钟，不占 scoreboard；LEA.LO 把它左移 id_bits 位并或上 site_id + 1；一条 ULOP3 把计数器掩码成环下标，一条 UIMAD.WIDE 把它变成表项地址；一条 STG.E 把这个字写到槽位基址之后 32 字节处；UIADD3 推进计数器。VALUE 记录多一条值的 store。warp 模式只从一个 lane 存储：ELECT P 选出它并守护各条 store，所以一个死谓词是默认形式的一部分 templates.py:736–768。没有死谓词时有两种后备：noelect，32 个 lane 全部存储同样的字节（GPR 值先用 R2UR 变成 uniform）；psave，借用 kernel 的活跃谓词，每个 lane 把自己的那一位存进一个死 GPR，最后一条受守护的 store 之后由 ISETP 恢复 templates.py:670–687。模板不含控制流：拼接器原样插入 island，不重定位其中任何东西，所以被选 lane 是一个谓词，环下标是一个掩码。

EXIT: the calibrationEXIT：校准

Before every EXIT an island reads %globaltimer and the SM clock together, copies the counter into a GPR and stores (gt_end, clk_end, n_records) as one 16-byte store into the header's second half, so the three are always self-consistent; a predicated EXIT the warp passes only makes a later calibration overwrite this one. The template has six register shapes, down to five single GPRs with a branch-free fix-up for a timer wrap between the HI and LO reads, or one bare even pair, because the last instructions of small kernels have very few dead registers templates.py:593–655.

每条 EXIT 之前有一个 island 一起读 %globaltimer 和 SM 时钟，把计数器复制进一个 GPR，并用一条 16 字节 store 把 (gt_end, clk_end, n_records) 写进头部的后一半，所以三者永远自洽；warp 越过的带谓词 EXIT 只会让后面的校准覆盖这一次。模板有六种寄存器形状，直到五个单独的 GPR 加上对 HI、LO 两次读之间计时器回绕的无分支修正，或者只有一对裸的偶数寄存器，因为小 kernel 的最后几条指令几乎没有死寄存器 templates.py:593–655。

Why the persistent state is three uniform registers为什么持久状态是三个 uniform 寄存器

INIT keeps three 32-bit registers live until exit: the slot base pair and the counter. In warp mode they are URs for two reasons. Uniform state is shared by the whole warp, so records made under divergence by different lane groups each take the next ring entry, where per-lane GPR state would let the groups overwrite each other's records. And URs survive USETMAXREG, so one INIT at kernel entry serves every warp role of a warp-specialised kernel, where GPR state above a role's new cap would be gone templates.py:18–26. Thread mode keeps GPRs and may need a hand-off around each role split; the corpus runs warp mode.

INIT 让三个 32 位寄存器一直活到退出：槽位基址对和计数器。warp 模式下它们是 UR，原因有二。uniform 状态由整个 warp 共享，所以分歧之下不同 lane 组产生的记录各占下一个环表项，而每 lane 的 GPR 状态会让各组互相覆盖对方的记录。而且 UR 能在 USETMAXREG 之后幸存，所以 kernel 入口的一个 INIT 就能服务 warp 特化 kernel 的每一种角色，而高于角色新上限的 GPR 状态会丢失 templates.py:18–26。thread 模式保留 GPR，在每次角色切分前后可能需要一次交接；语料库运行的是 warp 模式。

The ring and the budget ladder环与预算阶梯

The counter counts records and never wraps; a record goes to entry count & (ring_depth − 1), so a slot that writes more than the depth overwrites its oldest records, and the decoder knows exactly which: the oldest surviving entry is n_records mod ring_depth record.py:127–143. Because n_records is in the header, a wrap is never silent: the runtime fails the run and repeats the set at the next power of two up to --max-ring, every attempt kept as d<depth>/. DeepGEMM k512's trace-pp warps write 130 records in a tile loop, so at the default depth of 64, 1,188 slots wrapped and the set was re-run at 256 (chapter 02's gate shows both attempts).

计数器数的是记录数，从不回绕；一条记录写到表项 count & (ring_depth − 1)，所以写入条数超过深度的槽位会覆盖最旧的记录，而解码器确切知道是哪些：最早幸存的表项是 n_records mod ring_depth record.py:127–143。因为 n_records 在头部里，回绕从不无声：运行时判这次运行失败，并以下一个 2 的幂重跑这个集合，直到 --max-ring，每次尝试都保留为 d<depth>/。DeepGEMM k512 的 trace-pp warp 在 tile 循环里写 130 条记录，所以在默认深度 64 下有 1,188 个槽位回绕，集合以 256 重跑（第 02 章的门展示了这两次尝试）。

Clocks and calibration时钟与校准

Record format v1 rests on measured clock facts, not datasheet ones clockfacts.py:1–26. The SM clock ticks once per cycle, 1.98 GHz on H200 and 2.07 GHz on GB300 under load, but it is not a time base: it is not reset at launch and SMs disagree by 6–12 ms on H200 and by up to about 1,150 s on GB300. %globaltimer is a time base, in 32 ns steps. So a record carries the cheap clock, and the slot's two (globaltimer, clock) pairs convert cycles to ns for that warp alone, with no frequency assumed; in the standalone proof the calibrated times land within [−28, +43] ns of the kernel's own timer reads on H200 and [−51, +62] ns on GB300 ENV.md:274–287. A record keeps only the low 32 − id_bits bits of the clock: 26 bits wrap every 33.9 ms on H200, so consecutive records of one slot must be closer than that, and the decoder unwraps backwards from clk_end. The calibration is exact integer arithmetic: a float offset added to a ~1.8 × 1018 ns globaltimer resolves only to 256 ns decode.py:1–15.

记录格式 v1 建立在测量得到的时钟事实上，而不是数据手册上的 clockfacts.py:1–26。SM 时钟每周期走一格，负载下 H200 为 1.98 GHz、GB300 为 2.07 GHz，但它不是时间基准：启动时不复位，各 SM 之间在 H200 上相差 6–12 ms，在 GB300 上最多相差约 1,150 s。%globaltimer 才是时间基准，步长 32 ns。所以记录携带便宜的时钟，槽位的两对（globaltimer, clock）只为这个 warp 把周期换成 ns，不假设频率；在独立证明中，校准后的时间与 kernel 自己读到的计时器相差在 H200 上为 [−28, +43] ns，在 GB300 上为 [−51, +62] ns ENV.md:274–287。一条记录只保留时钟低 32 − id_bits 位：26 位在 H200 上每 33.9 ms 回绕一次，所以同一槽位相邻记录的间隔必须小于它，解码器从 clk_end 向后展开。校准是精确的整数运算：往约 1.8 × 1018 ns 的 globaltimer 上加一个浮点偏移，分辨率只有 256 ns decode.py:1–15。

Two architectures, one template两种架构，一套模板

Every probe instruction has the same text on sm_90 and sm_103; only the facts in probe_arch differ, and each body is encoded and decoded back to its own text on both arches by the tests templates.py:98–121. The constant bank moved wholesale: parameters, the stack pointer and the launch-geometry words all have new offsets, so INIT reads them from a table and never hard-codes one (DECISIONS 80) arch.py:61–68.

每条探针指令在 sm_90 与 sm_103 上文本相同；不同的只有 probe_arch 里的事实，而且测试在两种架构上把每个主体编码后再解码回它自己的文本 templates.py:98–121。常量 bank 整体搬了家：参数、栈指针和启动几何字都有新的偏移，所以 INIT 从一张表里读它们，从不写死任何一个（DECISIONS 80）arch.py:61–68。

The standalone proof独立证明

Before any splicer or runtime exists for an arch, the templates are proven alone: a hand-assembled kernel runs INIT, records of every kind, a divergent branch and the EXIT calibration on a 3-D grid of 3-D blocks with a partial last warp, into a poisoned buffer with guard bands; every slot is then decoded with decode_slot and checked for header validity, record count, site order, exact values, monotonic unwrapped clocks, ns against the kernel's own timer reads, and no byte written outside the header and records, and the same kernel without probes must give identical output standalone.py:1–22. This is the probes layer's share of invariant 5.

在某个架构上还没有任何拼接器或运行时之前，模板先被单独证明：一个手工汇编的 kernel 在一个 3 维 grid、3 维 block、最后一个 warp 不满的配置上运行 INIT、各种记录、一个分歧分支和 EXIT 校准，写进带保护带的投毒缓冲区；随后每个槽位用 decode_slot 解码，核对头部有效、记录数、站点顺序、精确的值、单调的展开时钟、与 kernel 自己读到的计时器相比的 ns，以及头部与记录之外没有任何字节被写，而同一个 kernel 不带探针时必须给出相同的输出 standalone.py:1–22。这是探针层在不变量 5 中承担的那一份。

§4Where it came from从何而来

The paper's probe library is where the shape comes from: an INIT that takes the warp's slot from the launch geometry and keeps three registers live for the rest of the kernel, and RECORD probes that write a timestamp or a value into that slot paper §4.5. Its clock scheme is the one record format v1 implements: the cheap per-SM clock in every record, calibrated per warp against the global timer rather than converted with an assumed frequency paper §A.2.1. Record format v1 fixes the bits of that design (DECISIONS 11): the ring with its monotonic count, the + 1 that makes zero mean empty, and the EXIT island that writes the second anchor and the count as one self-consistent store. The fallback record forms for sites without dead registers are Olympus's own.

形状来自论文的探针库：一个从启动几何得到 warp 槽位、并在 kernel 剩余部分保持三个寄存器活跃的 INIT，以及往槽位里写时间戳或值的 RECORD 探针 论文 §4.5。它的时钟方案正是记录格式 v1 所实现的：每条记录带便宜的 SM 时钟，按 warp 对照全局计时器校准，而不是用假设的频率换算 论文 §A.2.1。记录格式 v1 把这个设计落实到每一位（DECISIONS 11）：带单调计数的环、让零表示空的 + 1，以及把第二个锚点和计数用一条自洽的 store 写出的 EXIT island。为没有死寄存器的站点准备的后备记录形式是 Olympus 自己的。

Where Olympus departs: the clock read costs cycles, not hundreds of nsOlympus 的不同之处：读时钟花的是几个周期，不是几百 nsDECISIONS 40

The paper gives a global-timer read a cost of hundreds of nanoseconds. Olympus measured both clocks on H200: a CS2R of either costs 4–6 cycles, while the scoreboarded S2R and S2UR cost 27 and 37. The record keeps the SM clock anyway, because it is one 32-bit word and because the global timer's 32 ns steps are too coarse for consecutive sites; but every INIT and EXIT reads both with CS2R, which is what makes the per-slot calibration cheap enough to run on every warp DECISIONS.md:102–108.

论文给一次全局计时器读取标的代价是几百纳秒。Olympus 在 H200 上测了两个时钟：任一时钟的 CS2R 花 4–6 个周期，而经 scoreboard 的 S2R、S2UR 花 27 和 37 个周期。记录仍然保留 SM 时钟，因为它只占一个 32 位字，也因为全局计时器 32 ns 的步长对相邻站点太粗；但每个 INIT 和 EXIT 都用 CS2R 把两者都读一遍，这正是让每槽位校准便宜到能在每个 warp 上运行的原因 DECISIONS.md:102–108。

Where Olympus departs: a fence that assumes no latency model, and the bug it hadOlympus 的不同之处：不依赖任何延迟模型的围栏，以及它曾有的 bugDECISIONS 65

The paper schedules probes with its cost model from the start. Olympus's first planner instead wraps each bare body in a conservative fence: two leading NOPs, every instruction at stall 15, every variable-latency write and every store's source read on a scoreboard the next instruction waits for, and a trailing wait on all six, so the body is correct whatever the latency tables say templates.py:270–286. The fence had one bug, found by fuzzing, not by the sweep: its wait-on-everything sat on the first NOP, so after a kernel instruction that claims a scoreboard with stall 1 the wait issued 1 cycle after the claim and missed it, and a VALUE probe read an in-flight destination (t0_smem_sync index 9 after LDG.E.CONSTANT R2, about 64,000 of 65,536 twin pairs wrong while the outputs stayed bit-exact). The wait now sits on the last lead NOP, at least 15 cycles after the kernel's previous instruction, the 2-cycle rule of invariant 4 applied to the fence itself DECISIONS.md:248–250.

论文从一开始就用它的代价模型调度探针。Olympus 的第一个规划器则把每个裸主体裹进一道保守围栏：开头两条 NOP，每条指令 stall 15，每个可变延迟写和每条 store 的源读都占一个 scoreboard 并由下一条指令等待，结尾等待全部六个，所以无论延迟表怎么说，主体都是正确的 templates.py:270–286。这道围栏有过一个 bug，由模糊测试而非扫描发现：它的全等待放在第一条 NOP 上，于是在一条以 stall 1 占用 scoreboard 的 kernel 指令之后，等待在占用后 1 个周期发射而错过了它，VALUE 探针读到了尚在途中的目的寄存器（t0_smem_sync 第 9 条、LDG.E.CONSTANT R2 之后，65,536 对孪生记录中约 64,000 对出错，而输出保持逐位一致）。现在等待放在最后一条前导 NOP 上，离 kernel 前一条指令至少 15 个周期，即把不变量 4 的 2 周期规则用在围栏自身 DECISIONS.md:248–250。

Where Olympus departs: psave, and the write pointer that stayed a counterOlympus 的不同之处：psave，以及仍是计数器的写指针DECISIONS 71

Two template changes were tried against the overhead target. psave, an elect on a borrowed live predicate instead of the 32-lane noelect store, was mixed everywhere (matmul trace-mem −1.32 points, FlashMLA +0.52), because overhead follows the number of inserted instructions rather than the cost model's 515 vs 30 cycles; it is on by default only where its record is shorter, for 64-bit GPR values, which moved matmul trace-mem from +21.44% to +20.18% with every gate re-passed. A persistent write pointer in place of the counter was dropped: on the islands both plans keep it changed 0.0%, since the ring arithmetic runs beside the clock → store chain, not on it, and a correct form would have needed a read claim or a copy and a format v2 DECISIONS.md:328–341.

针对开销目标试过两处模板改动。psave，即在借来的活跃谓词上做 elect，代替 32 lane 的 noelect store，在所有地方启用时好坏参半（matmul trace-mem −1.32 个百分点，FlashMLA +0.52），因为开销跟随插入指令的数量，而不是代价模型里的 515 对 30 个周期；它只在记录更短的地方默认开启，即 64 位 GPR 值，这把 matmul trace-mem 从 +21.44% 降到 +20.18%，所有的门重新通过。用持久写指针代替计数器的方案被放弃：在两种计划都保留的 island 上它的改变是 0.0%，因为环运算与时钟 → store 链并行，不在链上；而正确的形式需要一次读占用或一次复制，以及格式 v2 DECISIONS.md:328–341。

这些就是探针写下的字节。悬停或点击一个头部字，看看 INIT 或 EXIT 放了什么进去；点击一个环表项，按 decode_slot 的方式一步步解码它的记录，直到整数纳秒。然后把 id_bits 从 6 调开，看时钟位缩短、回绕周期减半；或把环深度调到这个 warp 的 n_records 以下，看更小的环会丢掉哪些记录。
