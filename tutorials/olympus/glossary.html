Glossary术语

Each chapter defines its own words as it goes, which is what lets you start anywhere. This page is the other half of that arrangement: every word the edition defines, collected once, in the sentence its chapter defines it in rather than a paraphrase. Beside each word is the chapter that owns it, with its number, because a one-sentence gloss is a reminder and not an explanation — when it is not enough, the chapter is.

每一章都边走边定义自己用到的词，这正是你可以从任何一章开始读的原因。本页是这个安排的另一半：本教程定义过的每个词都在这里收一次，用的是它所在那一章原本的句子，而不是改写。每个词旁边写着拥有它的那一章和章号，因为一句话的释义只是提醒，不是解释——当它不够用时，那一章才够。

B

bubble气泡08Reading a trace读一份追踪

A bubble is a stretch of the lifetime that is not active: a gap between two consecutive blocks of leaf intervals, during which the warp was inside no innermost region at all.

气泡是生命期中不活跃的一段：两段连续叶子区间块之间的空隙，在这段时间里这个 warp 根本不在任何最内层 region 之内。

C

claim占用03Not getting in the way不碍事

A scoreboard is claimed when some instruction has set it and nothing has waited on it yet; the claim is outstanding, and the hardware will clear it when that operation completes.

当某条指令设置了一个 scoreboard 而还没有谁等待它时，这个 scoreboard 处于被占用状态；占用悬而未决，待那次操作完成后由硬件清除。

clock anchor时钟锚点08Reading a trace读一份追踪

Cycles become nanoseconds from the slot's own two clock anchors: (gt_start, clk_start) written by INIT and (gt_end, clk_end) written at the exit.

周期靠槽位自己的两个 clock anchor 换成纳秒：INIT 写下的 (gt_start, clk_start) 和退出处写下的 (gt_end, clk_end)。

code offset代码偏移06Writing probes into the binary把探针写进二进制

A code offset is any number in the file that means “byte n of this kernel’s text”, and inserting words invalidates every one of them at once.

代码偏移是文件里任何表示“本 kernel 代码段的第 n 字节”的数，而插入字会一下子使它们全部失效。

cost开销05Choosing registers and bits选择寄存器与控制位

A candidate's cost is o′ = t′[i(p)] − t0[i(p)]: the delay the island adds before the kernel's instruction at the insertion point.

一个候选的开销是 o′ = t′[i(p)] − t0[i(p)]：island 给插入点处 kernel 指令增加的延迟。

cubin01The binary二进制

A cubin is the file nvcc leaves behind for the GPU: an ELF64 object holding one block of machine code per kernel, plus the tables the driver and the profilers read.

cubin 就是 nvcc 为 GPU 留下的那个文件：一个 ELF64 目标文件，每个 kernel 一块机器码，再加上驱动和性能分析器要读的各种表。

D

dead已死02Knowing where it's safe知道哪里安全

A register is dead only when every path forward ignores it, which is why a register dead on one path is not dead at a point both paths reach.

只有当往前的每一条路径都不理它时，寄存器才算已死；这也是为什么在某一条路径上已死的寄存器，在两条路径都会到达的位置上并不已死。

divergence region分叉区域02Knowing where it's safe知道哪里安全

A divergence region starts at a branch that can split a group and ends at a cut: an instruction no lane passes until every non-exited lane of the warp has arrived there, such as WARPSYNC.ALL or the BSYNC of a convergence region.

一个分叉区域从可能分裂一组 lane 的分支开始，到一个切口（cut）结束：切口是这样一条指令，在 warp 中每个未退出的 lane 都到达它之前，没有任何 lane 能越过它，例如 WARPSYNC.ALL，或者某个汇合区域的 BSYNC。

E

EIATTR01The binary二进制

An EIATTR is one tag-length-value record; the tag is an id from NVIDIA's own eiattrs.inc, and the layer knows these ids because the splicer has to answer “does this record contain a code offset?” for every one of them eiattr.py:150–179.

一条 EIATTR 是一条“标签—长度—取值”记录；标签是 NVIDIA 自己的 eiattrs.inc 里的一个 id，而这一层认识这些 id，是因为拼接器必须对其中每一条回答“这条记录里有代码偏移吗？” eiattr.py:150–179。

F

filler word填充字06Writing probes into the binary把探针写进二进制

The null splice and the 128-byte tail padding use one filler word, ptxas’s own stall extender, printed below with its control bits.

空拼接和 128 字节的尾部填充用同一个填充字：ptxas 自己的 stall 延长器，连同控制位印在下面。

free_scoreboards(i)02Knowing where it's safe知道哪里安全

So this layer reports free_scoreboards(i) beside the dead registers: the scoreboards with no outstanding claim at that point.

所以这一层在死寄存器旁边报告 free_scoreboards(i)：该位置上没有未完成占用的 scoreboard。

G

guard band保护带07Running a traced kernel运行被追踪的 kernel

A guard band is 4,096 bytes filled with 0xA5, a byte no probe ever writes.

一条保护带是 4,096 字节的 0xA5，这是任何探针都不会写出的字节。

H

hint提示08Reading a trace读一份追踪

A hint names a source location and a pick rule, and resolves to an ordinary index site before anything is launched.

一条提示写明一个源码位置和一条挑选规则，并在任何东西启动之前解析成一个普通的下标站点。

I

interval区间08Reading a trace读一份追踪

Any record of a start site opens an interval and any record of an end site closes one; the interval's duration is the difference of the two timestamps.

任一起始站点的记录打开一个区间，任一结束站点的记录关上一个；区间的时长是两个时间戳之差。

island06Writing probes into the binary把探针写进二进制

So an island is a run of words inserted in front of one original instruction islands.py:1–24, and the consequence is that one old byte offset now needs two answers, not one.

于是一个 island 就是插在一条原始指令前面的一串字 islands.py:1–24，而结果是：一个旧的字节偏移现在需要两个答案，而不是一个。

L

leaf叶子08Reading a trace读一份追踪

Regions nest on purpose — a warp region spanning a whole lifetime, a tile region spanning one iteration, a wait inside it — and only the innermost ones are leaves, found by sweeping each row's intervals by decreasing start time and asking whether anything seen earlier in the sweep ends no later analysis.py:123–147.

region 是故意嵌套的——一个 warp region 跨越整个生命期，一个 tile region 跨越一次迭代，里面还有一次等待——只有最内层的才是叶子；找法是把每行的区间按起始时间递减扫一遍，问扫描中更早见到的区间里有没有哪个结束得不更晚 analysis.py:123–147。

lifetime生命期08Reading a trace读一份追踪

A row's lifetime is the hull of all its intervals, from its earliest start to its latest end.

一行的生命期是它所有区间的凸包，从最早的起点到最晚的终点。

N

null splice空拼接06Writing probes into the binary把探针写进二进制

A plan may ask for an island of n words that does nothing — that is how a null splice is built, to separate the cost of inserting code from the cost of the code itself — and the text is padded at the end to a multiple of 128 bytes.

一份计划可以要求一个由 n 个什么也不做的字组成的 island——空拼接就是这么做出来的，用以把“插入代码”的代价与“代码本身”的代价分开——而代码段末尾要被填充到 128 字节的整数倍。

O

.olyt08Reading a trace读一份追踪

It is a 64-byte host header — the magic OLYTRACE, a format version, and JSON metadata — followed by the device buffer exactly as it came back, one fixed-size slot per warp record.py:173–183.

它是一个 64 字节的宿主头部——魔数 OLYTRACE、格式版本和 JSON 元数据——后面紧跟原封不动带回来的设备缓冲区，每个 warp 一个定长槽位 record.py:173–183。

P

plan计划05Choosing registers and bits选择寄存器与控制位

What comes back is a plan — the kernel it is for, the sha256 of the cubin it was planned against, the layout of a trace record, the list of sites, and a rewriter(image, source) that will produce the patched binary.

返回的是一份计划——它所针对的 kernel、据以规划的那个 cubin 的 sha256、一条追踪记录的布局、站点列表，以及一个将产出补丁后二进制的 rewriter(image, source)。

probe探针04What a probe is探针是什么

So a probe is not a function, a callback or a trap: it is a list of SASS instructions.

所以探针不是函数、不是回调、也不是陷入：它就是一串 SASS 指令。

R

record记录04What a probe is探针是什么

A record must say two things — which site, and when — and it must cost one store, because the store is the part the kernel pays for.

一条记录必须说两件事——哪个站点、什么时候——而且必须只花一次 store，因为 store 才是 kernel 付的那部分代价。

refusal拒绝05Choosing registers and bits选择寄存器与控制位

Refusal comes in two forms, both before launch: a site whose value cannot be read before the site is left out of the plan with its reason in the report (SiteRefused) conservative.py:103–107, and an island with no free scoreboard is refused by the scheduler (ScheduleError).

拒绝有两种形式，都在启动之前：值在站点之前读不到的站点被排除在计划之外，原因写进报告（SiteRefused）conservative.py:103–107；没有空闲 scoreboard 的 island 由调度器拒绝（ScheduleError）。

region08Reading a trace读一份追踪

That bracket is a region: a name, a set of start site ids and a set of end site ids.

这个夹子就是 region：一个名字、一组起始站点 id 和一组结束站点 id。

relocation anchor重定位锚点06Writing probes into the binary把探针写进二进制

A relocation anchor is an instruction whose immediate is a byte offset measured from its own next pc, so moving the instruction changes what that immediate has to say.

重定位锚点指的是这样一条指令：它的立即数是一个以它自己的 next_pc 为基准量出的字节偏移，所以指令一挪位置，这个立即数该写什么也就变了。

ring环04What a probe is探针是什么

The counter counts records and never wraps; a record goes to entry count & (ring_depth − 1).

计数器数的是记录数，从不回绕；一条记录写到表项 count & (ring_depth − 1)。

row行08Reading a trace读一份追踪

A “row” is a warp for a warp-granularity trace and a thread for a per-thread one, and it is the unit every later stage groups by model.py:1–18.

“行”在 warp 粒度的追踪里是一个 warp，在逐线程的追踪里是一个线程，它是之后每一阶段的分组单位 model.py:1–18。

S

SASS01The binary二进制

The machine code is SASS, NVIDIA's real instruction set, and it is not documented.

那些机器码是 SASS，NVIDIA 真正的指令集，而它没有文档。

scoreboard02Knowing where it's safe知道哪里安全

A scoreboard is one of six per-warp counters, SB0 to SB5 (chapter 01), that the hardware uses to track work still in flight; the kernel claims one when it starts a load and waits on it when it needs the result.

scoreboard 是每个 warp 六个计数器之一，SB0 到 SB5（第 01 章），硬件用它们跟踪仍在途的工作；kernel 启动一次 load 时占用一个，需要结果时等待它。

set集合00The promise承诺

A set is a named list of sites and regions, pinned to one cubin's sha256 so that a set can never be applied to a binary it was not written for.

set（集合）是一份有名字的站点与 region 列表，钉在某个 cubin 的 sha256 上，这样一份集合绝不会被用在不是为它写的二进制上。

site站点06Writing probes into the binary把探针写进二进制

A site is an instruction index i, and its probe must run before instruction i on every path that reaches i — including a branch that jumps straight to i, and whether or not i's own predicate guard turns out to pass (DECISIONS 10) ir.py:24–33.

一个站点是一个指令下标 i，而它的探针必须在每一条到达 i 的路径上都在指令 i 之前执行——包括直接跳到 i 的分支，也不论 i 自己的谓词 guard 最终是否通过（DECISIONS 10）ir.py:24–33。

slot槽位04What a probe is探针是什么

A slot is a 32-byte header followed by a ring of ring_depth records, the whole slot padded up to a multiple of 32 bytes record.py:1–26.

一个槽位是 32 字节头部，之后是 ring_depth 条记录的环，整个槽位补齐到 32 字节的倍数 record.py:1–26。

splice拼接00The promise承诺

Olympus does this by splicing probes into the SASS the compiler already scheduled — writing a few extra instructions into the compiled binary itself, with no recompile and no edit to the source.

Olympus 的做法是把探针拼接（splice）进编译器已经调度好的 SASS——把几条额外指令写进编译好的二进制本身，不重新编译，也不改源码。

stall countstall 计数03Not getting in the way不碍事

A stall count buys exactly one thing: provable cycles between two issues, at most 15 at a time.

stall 计数买到的东西只有一样：两次发射之间可证明的周期数，一次最多 15 个。

T

T0 · T1–T4语料库分档01The binary二进制

T0 is the corpus's bottom tier, ten small kernels carrying one hazard or control-flow feature each, written so the right answer is known before Olympus runs; T1 to T4 above it are real kernels, Triton, CUTLASS, DeepGEMM and FlashMLA, and closed-source cuBLAS.

T0 是语料库最底层的一档，十个小 kernel，每个只带一种冒险或控制流特征，写成这样是为了在 Olympus 跑之前就知道正确答案；之上的 T1 到 T4 是真实 kernel：Triton、CUTLASS、DeepGEMM 与 FlashMLA，以及闭源的 cuBLAS。

template模板04What a probe is探针是什么

A template is the Python function that writes that list for one architecture, and the list it hands back is the probe's body.

模板是为某一种架构写出这串指令的 Python 函数，它交回来的这串指令就是探针的主体。

trace.json08Reading a trace读一份追踪

trace.json is the derived side: one JSON document, schema olympus-trace/1, holding source (the provenance of §2), launch and launches, counts, span, then sites with each site's records and source location, regions with each region's duration distribution and pairing counts, roles, activity, bubbles, concurrency, outliers, issues, timing and files.

trace.json 是推导出来的那一侧：一份 JSON 文档，schema olympus-trace/1，包含 source（§2 里的来源信息）、launch 与 launches、counts、span，然后是带每个站点记录数与源码位置的 sites、带每个 region 时长分布与配对计数的 regions，以及 roles、activity、bubbles、concurrency、outliers、issues、timing 和 files。

U

USETMAXREG02Knowing where it's safe知道哪里安全

USETMAXREG is the instruction a warp uses to change its own register budget, which is how a warp-specialized kernel gives its producer warps a small budget and its consumer warps a large one and lets them trade at runtime.

USETMAXREG 是 warp 用来改变自己寄存器预算的指令；warp 专门化的 kernel 正是靠它给 producer warp 小预算、给 consumer warp 大预算，并让它们在运行时互相交换。

W

wait mask等待掩码03Not getting in the way不碍事

Each instruction can set one write scoreboard (wr_sb: my destination register is not written yet) and one read scoreboard (rd_sb: I will read my source registers later, so do not overwrite them yet), and can wait on any subset of the six through its 6-bit wait mask or through a DEPBAR.LE instruction.

每条指令可以设置一个写 scoreboard（wr_sb：我的目的寄存器还没写好）和一个读 scoreboard（rd_sb：我稍后才读我的源寄存器，先别覆盖它们），并通过 6 位等待掩码或一条 DEPBAR.LE 指令等待这六个中的任意子集。

work budget工作量预算05Choosing registers and bits选择寄存器与控制位

Each site island gets WORK_BUDGET = 5,000 work units; every DFS node, leaf, dependency edge, kernel-context gap, renamed word and register placement is charged a calibrated number of units, about one microsecond each, so the plan is the same on every machine and in every run search.py:80–96.

每个站点 island 有 WORK_BUDGET = 5,000 个工作量单位；每个 DFS 节点、叶子、依赖边、kernel 上下文间距查询、重命名的指令字和寄存器放置都按校准过的单位数计费，每单位约一微秒，于是计划在每台机器、每次运行上都相同 search.py:80–96。
