How we know我们如何确信

Eight chapters have made claims: the kernel's instructions are untouched, every probe register is dead, no probe waits on the kernel, nothing runs unchecked. This chapter is where those claims are tested, without a second tracer to compare against. Each check is independent code that shares nothing with what it checks, each has a negative control where one is possible, and each leaves a run record that names the commit and the cubin it ran on. Then the results, once.

前面八章做出了许多断言：kernel 的指令原封不动，探针用的每个寄存器都已死，没有探针等待 kernel，没有检查过的东西不会运行。这一章就是检验这些断言的地方，而且不依赖第二个追踪工具来对照。每项检查都是独立的代码，与被检查的对象不共享任何东西；凡是可能的地方都有阴性对照；每次检查都留下一份运行记录，写明它所运行的提交和 cubin。然后，把结果呈现一次。

§1Contract契约

What this layer promises这一层的承诺

Every claim in this tutorial has a check, and every check has a run record you can trace to a commit and a cubin. The tools may import anything; nothing imports them.

本教程中的每条断言都有一项检查，每项检查都有一份能追溯到某个提交和某个 cubin 的运行记录。工具可以导入任何东西；没有任何东西导入工具。

olympus/verify → checks检查 olympus/* · olympus/env → a run record under every result in给每个结果一份运行记录，位于 /ws/runs

The reader relies on it: the invariants of chapters 00 to 08 are claims until something tests them. The tools row is the top of the import order, so a check cannot share code with what it checks; tests/test_layering.py asserts that importing the core loads nothing from this row verify/__init__.py:1–17. Where a check needs a second opinion, it takes it from outside Olympus: cuobjdump's text, nvdisasm's line listings, the kernel's own reference outputs, the kernel's own control flow. Without this layer the rest is a design; with it, each design rule is a number with a directory behind it.

依赖它的是读者：第 00 到 08 章的不变量在被检验之前只是断言。工具这一行位于导入顺序的顶端，所以检查不可能与被检查的对象共享代码；tests/test_layering.py 断言导入核心时不会加载这一行的任何东西 verify/__init__.py:1–17。需要第二意见时，检查从 Olympus 之外取：cuobjdump 的文本、nvdisasm 的行号列表、kernel 自己的参考输出、kernel 自己的控制流。没有这一层，其余的只是一份设计；有了它，每条设计规则都是一个背后有目录的数字。

§2Invariant不变量

Invariant不变量6

Every result carries its provenance. Run records name the commit, the cubin's sha256, tool versions, the GPU and its clock; evidence runs come from clean exports of one commit.

每个结果都带着自己的来历。运行记录写明提交、cubin 的 sha256、工具版本、GPU 及其时钟；证据运行来自同一个提交的干净导出。

Checked by olympus provenance --require, which walks every run.json under a path and exits 1 unless every record is complete and clean, all name one commit, and no job directory lacks its record provenance.py:1–37. On the final pass: 22 / 22 result directories pass on 48360e9, and --from EVAL.md passes 29 / 30 cited runs EVAL.md:223–225.

检查方式：olympus provenance --require 遍历路径下的每个 run.json，除非每条记录完整且干净、全部指向同一个提交、且没有任何任务目录缺少记录，否则以 1 退出 provenance.py:1–37。在最终一轮上：22 / 22 个结果目录在 48360e9 上通过，--from EVAL.md 对被引用的运行通过 29 / 30 EVAL.md:223–225。

The weaker rule would be "every result has a record". The first audit showed why that is not enough: of 12,953 records, 4,739 came from a dirty tree, and none of the 11 runs the evaluation then cited was clean; one sweep spanned seven commits, because its jobs read the shared tree's REVISION while other agents synced DECISIONS.md:287–304. So evidence runs come from a git archive export of one commit, written with its own REVISION under a temporary name and renamed only when complete export.sh:1–12. The other five invariants are each protected by a check in the next section; this one makes those checks citable.

更弱的规则会是"每个结果都有一份记录"。第一次审计说明了为什么这不够：12,953 条记录里有 4,739 条来自脏树，当时评估引用的 11 次运行没有一次是干净的；有一次扫描横跨了七个提交，因为它的任务在别的 agent 同步时读了共享树的 REVISION DECISIONS.md:287–304。所以证据运行来自对单个提交的 git archive 导出，连同它自己的 REVISION 先写到临时名字下，完整之后才改名 export.sh:1–12。另外五条不变量各由下一节的一项检查保护；这一条让那些检查可以被引用。

§4Where it came from从何而来

The paper's evaluation measures what a splice does to the binary, as changed basic blocks and preserved instructions paper §5.3, the end-to-end overhead per probe set paper §5.4.2, whether registers had to be added paper §5.5, and analysis and search time paper §5.6. Olympus's A2, A4, A3 and A8 are those four measurements turned into acceptance tests with thresholds, run over a corpus of twenty kernels and three probe sets each.

论文的评估测量一次拼接对二进制做了什么，以被改动的基本块和被保留的指令计 论文 §5.3；每个探针集合的端到端开销 论文 §5.4.2；是否不得不增加寄存器 论文 §5.5；以及分析与搜索的耗时 论文 §5.6。Olympus 的 A2、A4、A3 和 A8 就是这四项测量变成带阈值的验收测试，在二十个 kernel、每个三个探针集合的语料库上运行。

Beyond the paper: equality of outputs, and a check that attacks the analysis论文之外：输出相等，以及一项攻击分析本身的检查

Binary similarity says the kernel's instructions are still there; it does not say the kernel still computes the same thing. Olympus requires both: every traced run must reproduce the original's outputs bit for bit, with a canary that must fail, and the liveness analysis is tested directly by overwriting what it calls dead, with controls that overwrite what it calls live. The two liveness bugs the dead-register check found (the two GPRs sm_90 reserves at the top of the file; the wgmma fence windows) are why it is a standing check and not a one-time experiment.

二进制相似度说明 kernel 的指令还在；它不说明 kernel 算的还是同一件事。Olympus 两者都要求：每次追踪运行都必须逐位复现原 kernel 的输出，并有一个必须失败的 canary；活跃性分析则被直接检验，改写它判为已死的寄存器，再用改写它判为活跃的寄存器做对照。死寄存器检查找出的两个活跃性 bug（sm_90 在寄存器堆顶部保留的两个 GPR；wgmma 的 fence 窗口），正是它成为常设检查、而非一次性实验的原因。

Beyond the paper: evidence from clean exports only论文之外：证据只来自干净导出DECISIONS 68

A paper reports numbers; Olympus reports directories. Each row of the acceptance matrix cites run directories that pass olympus provenance --require, every record complete, clean and naming one commit, and the final pass was re-run from a frozen export after the first audit found no cited run that qualified DECISIONS.md:287–304. scripts/reproduce.md gives the command for each evidence class, its GPU and its cost.

论文报告数字；Olympus 报告目录。验收矩阵的每一行都引用通过 olympus provenance --require 的运行目录，每条记录完整、干净、指向同一个提交；第一次审计发现没有一次被引用的运行合格之后，最终一轮从冻结的导出重新运行 DECISIONS.md:287–304。scripts/reproduce.md 给出每类证据的命令、所用 GPU 和耗时。

History: what the comparison with G-Watch taught us历史：与 G-Watch 的比较教会了我们什么DECISIONS 92

During the evaluation a second tracer, G-Watch 0.0.35, ran the same corpus, sites and inputs from a clean export of its own; A5 was defined against it, and it is the "reference tracer" of the A5 row above. Its images taught us where timing artifacts come from: on T1–T4 its probes alter 828 original instructions, every one by adding scoreboards to a wait mask, and 12% of those added waits make the kernel wait early on its own asynchronous work, such as a SYNCS.ARRIVE waiting on a UTMACMDFLUSH EVAL.md:37–44. A probe waiting on the kernel's TMA-store scoreboard is what held DeepGEMM's B-scale barrier for about 1.2 µs, and it is behind 9 of the 16 A5 exceedances EVAL.md:96–105; the same artifact appeared in Olympus's own fenced planner until invariant 3 became a rule (DECISIONS 61), and the final scoreboard scan finds no Olympus island waiting on a kernel scoreboard. Since then Olympus is its own tracing system: G-Watch is not a reference for its results, the comparison tooling was removed, and EVAL.md stays as the record of the finished evaluation DECISIONS.md:621–629.

评估期间，第二个追踪工具 G-Watch 0.0.35 从它自己的干净导出出发，在相同的语料库、站点和输入上运行；A5 是相对它定义的，它就是上表 A5 一行里的"参照追踪器"。它的镜像教会我们计时伪影从哪里来：在 T1–T4 上，它的探针改动了 828 条原始指令，每一条都是往等待掩码里加 scoreboard，其中 12% 让 kernel 提前等待自己的异步工作，比如一条 SYNCS.ARRIVE 等待一条 UTMACMDFLUSH EVAL.md:37–44。等待 kernel 的 TMA store scoreboard 的探针，正是把 DeepGEMM 的 B-scale barrier 拖住约 1.2 µs 的原因，也是 A5 的 16 个超出中 9 个的来由 EVAL.md:96–105；同样的伪影也曾出现在 Olympus 自己的加围栏规划器里，直到不变量 3 成为规则（DECISIONS 61），而最终的 scoreboard 扫描找不到任何等待 kernel scoreboard 的 Olympus island。此后 Olympus 是它自己的追踪系统：G-Watch 不是它结果的参照，比较工具已被移除，EVAL.md 作为那次已完成评估的记录保留 DECISIONS.md:621–629。
