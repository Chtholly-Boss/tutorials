Reading a trace读一份追踪

A traced run leaves one file of records. This layer turns it into the thing you read: records become per-warp intervals, intervals become paired regions, and the result is one analysis block, trace.json, that olympus show prints as a header, per-region stats, the bubbles between regions and a timeline. When the cubin carries DWARF line tables, every site also names its source line. The block is complete on its own: nothing you read is re-derived from raw records.

一次追踪运行留下一个记录文件。这一层把它变成你要读的东西：记录变成每个 warp 的区间，区间配对成 region，结果是一个分析块 trace.json，olympus show 把它打印成头部、每个 region 的统计、region 之间的气泡和一条时间线。当 cubin 带有 DWARF 行表时，每个站点还会给出它的源码行。这个块自身是完整的：你读到的任何数字都不是从原始记录重新推导的。

§1Contract契约

What this layer promises这一层的承诺

One analysis block per trace, with each site's source location when the cubin has line tables, printed so that an agent can read where a kernel waits from the text alone.

每份追踪一个分析块，cubin 带行表时附上每个站点的源码位置，并打印成 agent 只凭文本就能读出 kernel 在哪里等待的样子。

olympus/trace · olympus/report → used by使用者 you, or an agent你，或一个 agent · reads读取 olympus/runtime's .olyt 写出的 .olyt

This is the layer the rest of the system exists for. The runtime (chapter 02) hands it a .olyt file: a 64-byte header with JSON metadata, then the raw device buffer, one slot per warp record.py:1–25. Everything the reader needs is derived once, written as trace.json (schema olympus-trace/1) with two numpy sidecars, and from then on only read analysis.py:1–13.

系统其余部分都是为这一层存在的。运行时（第 02 章）交给它一个 .olyt 文件：64 字节的头部带 JSON 元数据，之后是原始设备缓冲区，每个 warp 一个槽位 record.py:1–25。读者需要的一切只推导一次，写成 trace.json（schema olympus-trace/1）和两个 numpy 附件，此后只读不算 analysis.py:1–13。

§2Invariant不变量

Invariant不变量6

Every result carries its provenance. A trace names the binary it came from, the sites file and its sha256, the run record, and the cubin whose line table gave each source location; and every number in a view is the analysis block's, computed under one set of definitions.

每个结果都带着来源。一份追踪写明它来自哪个二进制、哪份站点文件及其 sha256、运行记录，以及给出每个源码位置的那个 cubin 的行表；视图中的每个数字都来自分析块，按同一套定义计算。

Checked by analysis.validate on every block it writes analysis.py:677–683, show.self_check, which recomputes the whole run through the filter path and lists any number that differs show.py:906–958, and olympus provenance --require on evidence runs.

检查方式：analysis.validate 检查它写出的每个块 analysis.py:677–683；show.self_check 把整次运行从过滤路径重算一遍，列出任何不一致的数字 show.py:906–958；证据运行还要过 olympus provenance --require。

The reading layer protects no byte of the kernel, so its invariant is about trust in what it prints. A filtered view (--block, --stime, --select) is recomputed from the sidecars with the analysis block's own definitions: stats from the intervals of the selected rows that overlap the window, bubbles from each row's full timeline clipped to the window; counts that need raw records (pair rate, unclosed starts) are shown only unfiltered and are null in a filtered --json show.py:35–41. The alternative, a reader that re-derives percentiles its own way, would quietly disagree with the block.

阅读层不保护 kernel 的任何一个字节，所以它的不变量关乎对它所打印内容的信任。过滤后的视图（--block、--stime、--select）从附件中按分析块自己的定义重算：统计取选中行里与窗口重叠的区间，气泡在每行完整的时间线上算好再裁到窗口；需要原始记录的计数（配对率、未闭合的起点）只在未过滤时显示，在过滤后的 --json 中为 null show.py:35–41。另一种做法，让读者自己用自己的方式重算百分位，会悄悄地与分析块不一致。

§3How it works如何工作

Records → intervals → regions记录 → 区间 → region

A record is one 32-bit word, (clock << 6) | (site_id + 1), so the decoder first unwraps the truncated SM clock, backwards from each slot's exit calibration, and converts cycles to integer nanoseconds with the slot's own (globaltimer, clock) pairs; no clock frequency is assumed decode.py:1–15. The result is a columnar Trace: one row per record with launch, warp, block, SM, site, timestamp and value model.py:1–18.

一条记录是一个 32 位字，(clock << 6) | (site_id + 1)，所以解码器先从每个槽位的退出校准点倒推、展开被截断的 SM 时钟，再用该槽位自己的（globaltimer, clock）对把周期换成整数纳秒；不假设任何时钟频率 decode.py:1–15。结果是一张列式的 Trace：每条记录一行，带 launch、warp、block、SM、站点、时间戳和值 model.py:1–18。

Pairing turns a warp's records into intervals, one region at a time: a record of any start site opens an interval and a record of any end site closes it. close: first closes at the first end record; close: last keeps moving the close until the region's next start, which is how a warp's lifetime ends at its last exit record rather than its first; open: first absorbs repeated starts, so a polling loop counts from its first iteration ir.py:48–69. The reference implementation is kept as the executable spec; a vectorised one computes exactly the same intervals for millions of records, and a test checks the two against each other on random sequences pairing.py:1–15.

配对把一个 warp 的记录变成区间，一次处理一个 region：任一起始站点的记录打开一个区间，任一结束站点的记录把它关上。close: first 在第一条结束记录处关闭；close: last 一直把关闭点往后挪，直到该 region 的下一次开始，这就是 warp 的生命期结束于最后一条退出记录而非第一条的原因；open: first 吸收重复的开始，于是轮询循环从第一次迭代算起 ir.py:48–69。参考实现作为可执行的规范保留；向量化实现对数百万条记录算出完全相同的区间，一个测试在随机序列上对比两者 pairing.py:1–15。

The analysis block分析块

trace.json holds, per region, a duration distribution with nearest-rank percentiles, the pair rate and its failure counts, and the share of its intervals that are leaves, intervals that contain no other region's interval. Leaves are what make bubbles well defined: a row's active time is the union of its leaf intervals, so an envelope region such as warp cannot hide the gaps inside it, and a bubble is lifetime minus active, named by the leaf region before and after the gap analysis.py:49–68. Roles group warps (producer, consumer, math) so that stragglers are z-scored against their own kind.

trace.json为每个 region 保存一个时长分布（最近秩百分位）、配对率及其失败计数，以及其中叶子区间的占比：叶子是不包含任何其他 region 区间的区间。有了叶子，气泡才有良好定义：一行的活跃时间是它所有叶子区间的并集，于是像 warp 这样的包络 region 藏不住内部的空隙；气泡 = 生命期 − 活跃时间，用空隙前后的叶子 region 命名 analysis.py:49–68。角色把 warp 分组（producer、consumer、math），掉队者只与同类做 z 分数比较。

olympus showolympus show

With no flag, show prints the header, the per-region stats, the bubbles and an ASCII timeline; flags add sites, concurrency, outliers, the longest intervals of one region, the source view and the HTML panel show.py:1–33. Source lines, and why they are hints源码行，以及为什么它们只是提示

When the cubin has a DWARF line table, the analysis gives each site a source: file, line, the inlining chain as nvdisasm -g -gi prints it, and the text of that line dwarf_line.py:1–15. Sites can also be placed from source: a hint names a line and a pick rule (start, end, op=LDG) and resolves to an ordinary index site, pinned to the cubin's sha256 like any other; nothing downstream reads hints hints.py:1–11. show --source then prints each region's start and end lines, and --select FILE:LINE keeps the regions that start or end on a line:

cubin 带 DWARF 行表时，分析给每个站点一个 source：文件、行号、按 nvdisasm -g -gi 打印方式给出的内联链，以及该行的文本 dwarf_line.py:1–15。站点也可以从源码放置：一条提示写明一行和一条挑选规则（start、end、op=LDG），解析成一个普通的下标站点，和其他站点一样钉在 cubin 的 sha256 上；下游没有任何东西读提示 hints.py:1–11。随后 show --source 打印每个 region 的起止行，--select FILE:LINE 只保留在某一行开始或结束的 region：

That last command is the warning. In FlashAttention-3's unrolled main loop, ptxas gives two of the four producer K waits the V load's line, 764. A hint on that line finds a region whose p50 is 1.60 µs, but split by start site, the true V wait (s4) is 49 ns and the two K waits (s8, s9) are 1.6 µs each. The line table cannot tell K from V; the SASS can, by the barrier offset. So sites stay instruction indices, the reviewed sites.yaml stays the authority, and a hint is a convenience that resolves to one, with scatter and inlining warnings as part of its output (DECISIONS 78) USAGE.md:1035–1058.

最后那条命令就是警告。在 FlashAttention-3 展开的主循环里，ptxas 把四次 producer K 等待中的两次记在 V 加载的那一行（764）。放在这一行上的提示找到一个 p50 为 1.60 µs 的 region，但按起始站点拆开，真正的 V 等待（s4）是 49 ns，两次 K 等待（s8、s9）各 1.6 µs。行表分不清 K 和 V；SASS 分得清，靠 barrier 的偏移。所以站点仍是指令下标，经过审阅的 sites.yaml 仍是权威，提示只是解析成站点的一种便利，散布与内联的警告是它输出的一部分（DECISIONS 78）USAGE.md:1035–1058。

§4Where it came from从何而来

What a trace is for is the paper's opening argument: a counter-based profiler reports totals over a launch, while intra-kernel tracing says which stage of a fused kernel waited on which, from timestamps at chosen instructions paper §2.1. The paper's system places trace hints in the source and locates them in the binary through DWARF, and keeps a low-level interface at a program address because DWARF does not always preserve the source-to-binary mapping paper §3. Its trace driver appends the buffer address to the launch and walks the per-slot records afterwards paper §4.5.

追踪有什么用，是论文开篇的论点：基于计数器的 profiler 报告整次 launch 的总量，而 kernel 内追踪靠选定指令处的时间戳，说清融合 kernel 里哪个阶段在等哪个阶段 论文 §2.1。论文的系统把追踪标记放在源码里、通过 DWARF 在二进制中定位，同时保留一个按程序地址的底层接口，因为 DWARF 并不总能保住源码到二进制的映射 论文 §3。它的追踪驱动把缓冲区地址追加到 launch 上，事后遍历每个槽位的记录 论文 §4.5。

The same choice, with the measurement that justified keeping it同样的选择，以及支持保留它的测量DECISIONS 78

The paper keeps an address interface as a fallback. Olympus makes the index the authority and the source hint the convenience, after the FlashAttention-3 line table put K waits on the V line. Hints resolve to indices with warnings; the reviewed index file is what every tool reads DECISIONS.md:441–449.

论文把地址接口留作后备。Olympus 在 FlashAttention-3 的行表把 K 等待记到 V 行之后，把下标定为权威，把源码提示定为便利。提示解析成下标并附带警告；每个工具读的都是经过审阅的下标文件 DECISIONS.md:441–449。

Beyond the paper: line tables survive the splice论文之外：行表在拼接后仍然保留DECISIONS 79

A spliced cubin keeps its .debug_line and PTX line tables: an island takes the line of the instruction it precedes, which adds no rows, so the inlining references stay valid; the output is re-parsed and checked, and falls back to stripping if the check fails. On 43 spliced images every original instruction keeps its line and nvdisasm agrees, so a source view of a traced run is the source view of the kernel verify.py:11–15.

拼接后的 cubin 保留它的 .debug_line 和 PTX 行表：island 取它前面那条指令的行号，不增加任何行，于是内联引用保持有效；输出会被重新解析并检查，检查失败则退回到剥离行表。在 43 个拼接镜像上，每条原始指令都保住自己的行号，nvdisasm 一致，所以一次追踪运行的源码视图就是这个 kernel 的源码视图 verify.py:11–15。
