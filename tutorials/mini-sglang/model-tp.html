Models, TP and Kernels模型、张量并行与 kernel

How Mini-SGLang builds a decoder model out of tensor-parallel layers, slices a Hugging Face checkpoint for each rank as it streams from disk, runs MoE experts with two Triton GEMMs, issues its all-reduces through its own NCCL binding, and compiles the few custom kernels it needs.

Mini-SGLang 如何用张量并行的层搭出 decoder 模型，在从磁盘流式读取 Hugging Face checkpoint 时为每个 rank 切出自己的部分，用两个 Triton GEMM 跑 MoE 专家，通过自带的 NCCL 绑定发起 all-reduce，以及如何编译它需要的几个自定义 kernel。

§1A model is a tree of BaseOPs模型是一棵 BaseOP 树

Mini-SGLang doesn't use torch.nn.Module. Every layer derives from BaseOP, whose state_dict and load_state_dict walk the object's attributes: a tensor attribute is a parameter, a BaseOP attribute is a child, and names starting with _ are skipped layers/base.py:15–53. Loading pops each key, checks that shape and dtype match, and replaces the attribute with the loaded tensor. Keys left over at the top level raise an error, so a checkpoint that doesn't fit the model fails loudly.

Mini-SGLang 不用 torch.nn.Module。每个层都继承 BaseOP，其 state_dict 与 load_state_dict 遍历对象的属性：张量属性是参数，BaseOP 属性是子节点，以 _ 开头的名字被跳过 layers/base.py:15–53。加载时逐个弹出 key，检查形状与 dtype 一致，再用加载的张量替换该属性。顶层多余的 key 会直接报错，所以与模型对不上的 checkpoint 会显式失败。

That design pairs with how the engine builds the model: under torch.device("meta"), so constructing it allocates nothing, followed by load_state_dict with real tensors that simply take the place of the meta placeholders engine.py:49–52. The one exception is the RoPE cos/sin cache, which is computed at construction, so set_rope_device must name the real device first rotary.py:117–143.

这一设计与 engine 构建模型的方式配合：在 torch.device("meta") 下构造，不分配任何显存；随后用真实张量调用 load_state_dict，直接顶替 meta 占位张量 engine.py:49–52。唯一的例外是 RoPE 的 cos/sin 缓存，它在构造时就要算出来，所以必须先用 set_rope_device 指定真实设备 rotary.py:117–143。

Six architecture names map to five model files register.py:5–21, and they share almost everything. Each decoder layer is attention plus MLP between two fused add + RMSNorm steps, with the residual threaded through as a second return value qwen3.py:18–41. The attention and MLP blocks come from models/utils.py; the differences are flags models/utils.py:25–123:

六个架构名映射到五个模型文件 register.py:5–21，它们几乎共享一切。每个 decoder 层就是在两次融合 add + RMSNorm 之间放一个 attention 和一个 MLP，残差作为第二个返回值一路传递 qwen3.py:18–41。attention 与 MLP 块来自 models/utils.py，差异只是一些开关 models/utils.py:25–123：

Tensor parallelism is decided at construction. Each linear layer reads the global DistributedInfo (rank and size) distributed/info.py:6–35 and allocates only its local slice. There are five kinds linear.py:13–127:

张量并行在构造时就确定了。每个线性层读取全局的 DistributedInfo（rank 与 size）distributed/info.py:6–35，只分配本地切片。共有五种 linear.py:13–127：

Every split goes through div_even, which asserts exact division misc.py:20–26. KV heads are the one exception: with allow_replicate=True, a TP degree larger than the KV head count is allowed when it is a multiple of it, and each rank then holds one KV head that it shares with other ranks. Attention splits heads with the same rule, so the attention backend on each rank sees only its own heads attention.py:32–36.

所有切分都经过 div_even，它断言必须整除 misc.py:20–26。KV head 是唯一的例外：开启 allow_replicate=True 时，TP 度数可以大于 KV head 数，只要是其倍数即可，此时每个 rank 持有一个与其他 rank 共享的 KV head。attention 按同样的规则切分 head，所以每个 rank 上的 attention backend 只看到自己的 head attention.py:32–36。

The vocabulary is split by rows, with ⌈V / tp⌉ rows per rank. The embedding looks tokens up with a masked index kernel that writes zeros for tokens outside the local range, then all-reduces, so exactly one rank contributes each row embedding.py:14–42 index.cu:60–96. The LM head goes the other way. Each rank computes logits for its vocabulary slice, all-gathers them along the token dimension, and permutes the result so that vocabulary slices sit side by side. In prefill it first keeps only each request's last position embedding.py:87–110.

词表按行切分，每个 rank ⌈V / tp⌉ 行。embedding 用带掩码的 index kernel 查表，对不在本地范围内的 token 写零，再做 all-reduce，这样每一行恰好只由一个 rank 提供 embedding.py:14–42 index.cu:60–96。LM head 则反过来：每个 rank 为自己的词表切片算 logits，沿 token 维 all-gather，再重排使各词表切片并排。prefill 时它先只保留每个请求的最后一个位置 embedding.py:87–110。

    §3One layer, two all-reduces一层，两次 all-reduce

    The layers pair up the classic Megatron way. A column-parallel projection takes the full, replicated input and produces a slice. The ops in between work on that slice alone. A row-parallel projection turns the slice back into a full-width partial sum, and one all-reduce makes every rank hold the same activations again. Attention pairs qkv_proj with o_proj, and the MLP pairs gate_up_proj with down_proj. That gives two all-reduces per layer, both inside the row-parallel forward linear.py:91–127.

    这些层按经典的 Megatron 方式成对出现：列并行投影接收完整的复制输入，产出一个切片；中间的算子只处理这个切片；行并行投影把切片变回全宽的部分和，再用一次 all-reduce 让每个 rank 重新持有相同的激活。attention 里 qkv_proj 与 o_proj 成对，MLP 里 gate_up_proj 与 down_proj 成对。因此每层两次 all-reduce，都在行并行层的 forward 里 linear.py:91–127。

    Walk one layer across ranks below. The norms and the MoE router are replicated work, the projections and attention are sharded, and the Σ columns are the only points where ranks exchange data.

    在下面沿着各 rank 走完一层。归一化与 MoE router 是在各 rank 上重复的工作，投影与 attention 是切分后的工作，Σ 列是 rank 之间唯一交换数据的地方。

    Shapes are per rank for the listed model; T is the number of tokens in the batch. The PyNCCL buffer assumes the default --max-prefill-length 8192 (§6).

    形状是所列模型在单个 rank 上的形状；T 是批内 token 数。PyNCCL buffer 按默认的 --max-prefill-length 8192 计算（见 §6）。

    §4Loading and sharding a checkpoint加载并切分 checkpoint

    load_weight streams safetensors files one tensor at a time weight.py:75–124. For each Hugging Face key it cuts this rank's shard, merges projections the runtime keeps fused, stacks MoE experts, and yields the result already on the GPU. Its docstring sets the memory bound: one full tensor plus a small merge buffer on the CPU side. The slicing rule depends only on the key name:

    load_weight 按张量逐个流式读取 safetensors 文件 weight.py:75–124。对每个 Hugging Face key，它切出本 rank 的分片，合并运行时保持融合的投影，堆叠 MoE 专家，并直接产出已在 GPU 上的结果。其 docstring 给出了内存上界：CPU 侧一个完整张量加一个小的合并缓冲。切分规则只取决于 key 名：

    • Output-dimension splits (q, k, v, gate, up) take row chunks. When KV heads are fewer than ranks, rank r takes head r · kv / tp, which is how one KV head ends up on several ranks.
    • Input-dimension splits (o, down) take column chunks.
    • Everything else (norms, q/k norms, the MoE router) passes through whole.
    • Merging: the loader collects the per-rank q, k and v shards under qkv_proj and concatenates them only when all three have arrived; gate and up become gate_up_proj the same way weight.py:100–109. Because it concatenates shards, each rank's fused weight is [q_r | k_r | v_r], which is exactly the order AttentionLayer splits on.
    • Experts: in MoE models, keys matching ….experts.<i>.… wait until all experts of that projection are present and are then stacked into one [E, …] tensor weight.py:111–119. The loader asserts at the end that no merge or expert group was left incomplete.
    • 按输出维切分（q、k、v、gate、up）取行块。KV head 少于 rank 数时，rank r 取第 r · kv / tp 个 head，一个 KV head 就是这样出现在多个 rank 上的。
    • 按输入维切分（o、down）取列块。
    • 其余张量（norm、q/k norm、MoE router）原样传过。
    • 合并：加载器把本 rank 的 q、k、v 分片收集到 qkv_proj 名下，三者都到齐时才拼接；gate 与 up 同样合成 gate_up_proj weight.py:100–109。由于拼接的是分片，每个 rank 的融合权重是 [q_r | k_r | v_r]，正好是 AttentionLayer 切分的顺序。
    • 专家：MoE 模型中，匹配 ….experts.<i>.… 的 key 要等该投影的所有专家都到齐，再堆叠成一个 [E, …] 张量 weight.py:111–119。加载器最后断言没有残缺的合并组或专家组。

    The engine converts each yielded tensor to the serving dtype and passes the whole dictionary to load_state_dict. With --dummy-weight it skips the files and fills every parameter with random values of the right local shape engine.py:139–146.

    engine 把产出的每个张量转成服务用的 dtype，再把整个字典交给 load_state_dict。使用 --dummy-weight 时它跳过文件，用正确本地形状的随机值填满所有参数 engine.py:139–146。

    §5The MoE pathMoE 路径

    Mini-SGLang runs MoE with tensor parallelism, not expert parallelism. Every rank holds all experts, each sliced along its intermediate dimension, so the local tensors are [E, 2·I/tp, H] and [E, H, I/tp] moe.py:33–43. The router is a replicated linear layer, so all ranks agree on routing without exchanging anything models/utils.py:53–76. After the experts run, a single all-reduce sums the partial outputs moe.py:57–58. The only backend is fused, which the engine selects automatically for MoE models moe/__init__.py:16–27 engine.py:231–233.

    Mini-SGLang 用张量并行而不是专家并行来跑 MoE。每个 rank 都持有全部专家，每个专家沿中间维切分，因此本地张量是 [E, 2·I/tp, H] 与 [E, H, I/tp] moe.py:33–43。router 是复制的线性层，所以各 rank 无需交换任何数据就能在路由上达成一致 models/utils.py:53–76。专家算完后，一次 all-reduce 对部分输出求和 moe.py:57–58。唯一的 backend 是 fused，engine 会为 MoE 模型自动选择它 moe/__init__.py:16–27 engine.py:231–233。

    1. Top-k. sgl_kernel.topk_softmax picks each token's experts and weights, optionally renormalized to sum to 1 fused.py:9–28.
    2. Align. moe_align_block_size sorts the flattened (token, k) rows by expert and pads each expert to a multiple of BLOCK_SIZE_M, so a GEMM tile never mixes experts fused.py:31–89.
    3. GEMM 1. A Triton kernel gathers token rows (row // top_k) and multiplies them by the tile's expert gate_up weights fused_moe.py:132–149.
    4. Activation. silu_and_mul over the whole intermediate cache.
    5. GEMM 2. The same kernel with top_k = 1 applies down weights and multiplies each row by its router weight fused_moe.py:183–185.
    6. Sum. moe_sum_reduce adds the top-k rows of each token in FP32 and writes the result over the input hidden states, which the layer returns fused.py:175–227.
    1. Top-k。sgl_kernel.topk_softmax 为每个 token 选出专家与权重，可选地重新归一化使和为 1 fused.py:9–28。
    2. 对齐。moe_align_block_size 把展平后的（token, k）行按专家排序，并把每个专家补齐到 BLOCK_SIZE_M 的倍数，使一个 GEMM tile 不会混入多个专家 fused.py:31–89。
    3. GEMM 1。Triton kernel 按 row // top_k 收集 token 行，乘以该 tile 所属专家的 gate_up 权重 fused_moe.py:132–149。
    4. 激活。对整个中间缓存做 silu_and_mul。
    5. GEMM 2。同一个 kernel、top_k = 1，乘以 down 权重，并把每行乘上它的 router 权重 fused_moe.py:183–185。

    §6PyNCCL: a thin NCCL bindingPyNCCL：一层很薄的 NCCL 绑定

    Layers never call NCCL directly. They hold a DistributedCommunicator, which forwards to the last plugin in a class-level list impl.py:63–70. The list starts with a torch.distributed implementation. When PyNCCL is on (the default; --disable-pynccl turns it off args.py:124–130), the engine starts a gloo CPU group and appends a PyNCCL plugin on top engine.py:113–137. Rank 0 creates the NCCL unique id and broadcasts it over that CPU group pynccl.py:45–78.

    各层从不直接调用 NCCL。它们持有一个 DistributedCommunicator，它把调用转发给类级列表中的最后一个插件 impl.py:63–70。列表初始是 torch.distributed 实现。开启 PyNCCL 时（默认开启，--disable-pynccl 可关闭 args.py:124–130），engine 建立 gloo CPU group，并在列表末尾追加 PyNCCL 插件 engine.py:113–137。rank 0 生成 NCCL unique id，并通过这个 CPU group 广播 pynccl.py:45–78。

    The binding is one C++ class, NCCLWrapper, exposed through tvm-ffi. Its constructor creates the communicator, allocates a buffer with ncclMemAlloc, and registers it as a window with NCCL_WIN_COLL_SYMMETRIC pynccl.cu:72–91. The buffer holds max_forward_len × hidden × dtype bytes, capped by MINISGL_PYNCCL_MAX_BUFFER_SIZE (1 GiB by default) env.py:70. Under the server, max_forward_len is the prefill chunk size scheduler/config.py:15–37, so any one layer's all-reduce fits.

    这个绑定只有一个 C++ 类 NCCLWrapper，通过 tvm-ffi 暴露出来。构造函数创建 communicator，用 ncclMemAlloc 分配一块 buffer，并以 NCCL_WIN_COLL_SYMMETRIC 注册为 window pynccl.cu:72–91。buffer 大小为 max_forward_len × hidden × dtype 字节数，上限为 MINISGL_PYNCCL_MAX_BUFFER_SIZE（默认 1 GiB）env.py:70。在 server 下，max_forward_len 就是 prefill 分块大小 scheduler/config.py:15–37，因此任意一层的 all-reduce 都放得下。

    An all-reduce that fits is copied into the registered buffer, reduced in place there, and copied back, all on the current stream. Anything larger is reduced in place in the caller's tensor. All-gather never uses the buffer and writes straight into the output tensor pynccl.cu:136–161. Only FP16 and BF16 are mapped to NCCL types pynccl.cu:59–63, which covers every tensor the layers reduce. The repo ships its own copy of the NCCL 2.27 header, so the window API compiles against a known version nccl227.h:19–24.

    能放进 buffer 的 all-reduce 会先拷进已注册的 buffer，在其中原地规约，再拷回去，全部在当前 stream 上完成。更大的则直接在调用方的张量上原地规约。all-gather 从不使用这块 buffer，直接写进输出张量 pynccl.cu:136–161。只有 FP16 与 BF16 映射到了 NCCL 类型 pynccl.cu:59–63，这涵盖了各层需要规约的所有张量。仓库自带一份 NCCL 2.27 头文件，window API 因此针对确定的版本编译 nccl227.h:19–24。

    Why the extra copies为什么要多拷贝两次

    The code doesn't say why it copies into a registered window instead of reducing in place. My reading: NCCL can pick its symmetric-memory algorithms only for buffers registered as symmetric windows, and activations come from PyTorch's allocator, so staging through one fixed buffer is the simple way to get that path. The copies are device-to-device and small for decode batches.

    代码没有说明为什么要拷进已注册的 window，而不是原地规约。我的理解是：NCCL 只有对注册为对称 window 的 buffer 才能选用对称内存算法，而激活来自 PyTorch 的分配器，所以借一块固定 buffer 中转是走这条路径的简单办法。这两次拷贝都是显存内拷贝，decode 批次下数据量很小。

    §7Custom kernels through tvm-ffi经由 tvm-ffi 的自定义 kernel

    Attention, norms, RoPE and activations come from FlashInfer, FlashAttention and sgl_kernel. Mini-SGLang writes only a few kernels itself: the embedding lookup, the KV-cache store, a radix-key compare and the NCCL wrapper. Chapter 02 covers the store and radix kernels. All of them are built at runtime through tvm_ffi.cpp, in one of two ways kernel/utils.py:53–129:

    attention、norm、RoPE 与激活函数来自 FlashInfer、FlashAttention 和 sgl_kernel。Mini-SGLang 自己只写了少数几个 kernel：embedding 查表、KV cache 写入、radix key 比较，以及 NCCL 包装。写入与 radix kernel 见第 02 章。它们都在运行时通过 tvm_ffi.cpp 构建，有两种方式 kernel/utils.py:53–129：

    • load_aot compiles fixed source files from csrc/src/ as one module. PyNCCL and the tensor self-test use it.
    • load_jit builds an inline source that #includes a file from csrc/jit/ and appends one TVM_FFI_DLL_EXPORT_TYPED_FUNC per wrapper. Template arguments are printed into the wrapper and into the module name (minisgl__index_…), so each configuration is its own compiled module, and functools.cache keeps it loaded.
    • load_aot 把 csrc/src/ 下的固定源文件编译成一个模块，PyNCCL 与张量自测用的就是它。
    • load_jit 生成一段内联源码，#include csrc/jit/ 下的某个文件，并为每个 wrapper 追加一行 TVM_FFI_DLL_EXPORT_TYPED_FUNC。模板参数会写进 wrapper 和模块名（minisgl__index_…），因此每种配置都是单独编译的模块，由 functools.cache 保持加载状态。

    On the C++ side, three helpers do most of the work. TensorMatcher checks shapes against symbolic sizes that must agree across tensors, for example {-1, D} for the weight and {L, D} for the output index.cu:103–126. LaunchKernel wraps cudaLaunchKernelEx and can set the programmatic-dependent-launch attribute. resolve_device asks tvm-ffi for the caller's current stream, which is how a kernel launched from Python lands on PyTorch's stream without passing it explicitly utils.cuh:91–125. For editing these files, python -m minisgl.kernel writes a .clangd config with the same include paths and the local GPU's architecture kernel/__main__.py:4–47.
